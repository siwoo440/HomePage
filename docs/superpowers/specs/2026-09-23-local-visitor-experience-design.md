# DEVFORGE 로컬 방문자 경험 강화 설계

## 1. 목적

외부 계정과 유료 서비스를 연결하지 않은 상태에서 DEVFORGE 공개 사이트를 운영 가능한 수준으로 정리하고, 방문자가 스튜디오와 프로젝트를 이해하고 다시 찾을 수 있는 로컬 기능을 제공한다.

## 2. 검증된 현재 상태

- 기존 자동 테스트 182개가 통과한다.
- 메인, 굿즈, 개발 뉴스, 커뮤니티와 로그인 화면에 처리되지 않은 브라우저 오류가 없다.
- 메인 페이지는 PC와 모바일 기준에서 의도하지 않은 가로 넘침이 없다.
- 공개 헤더에는 개발용 기기 선택기가 노출된다.
- 메인 페이지는 테스트용 상담 서비스와 외부 상담 스크립트를 직접 불러온다.
- 푸터에는 오래된 연도와 임시 운영자 이름이 표시된다.
- 메인 페이지에는 스튜디오 소개, 개발 현황, 즐겨찾기, 최근 본 프로젝트와 FAQ 영역이 없다.
- 모바일 필터 버튼 높이는 44px 기준보다 작다.

## 3. 범위

### 포함

1. 테스트·임시 운영 요소 정리
2. 히어로 행동 버튼과 핵심 현황 추가
3. 스튜디오 소개 추가
4. 프로젝트 개발 현황판 추가
5. 브라우저 로컬 즐겨찾기와 최근 본 프로젝트 추가
6. 굿즈·커뮤니티 준비 상태 표현 개선
7. 이용약관·개인정보처리방침 독립 초안 페이지 추가
8. 모바일·접근성 개선
9. 자동 테스트, 타입 검사, 빌드와 브라우저 검증

### 제외

- Supabase 실제 연결
- YouTube, SNS와 판매처 실제 연결
- ChannelIO 실제 운영 연결
- 실제 상품 판매
- Vercel 배포와 공식 도메인 연결
- 법률 전문가의 최종 검토
- 확인되지 않은 출시일, 회사 정보, 구성원 정보와 외부 주소 작성

## 4. 구조

- `public/site-experience.mjs`는 현황 집계, 로컬 저장값 정리, 즐겨찾기, 최근 본 프로젝트와 연도 표시를 담당한다.
- `public/site-experience.css`는 새 메인 영역과 모바일·접근성 보강을 담당한다.
- `public/support-widget.mjs`는 유효한 설정이 있을 때만 상담 스크립트를 불러오며 기본 상태에서는 외부 요청을 만들지 않는다.
- `public/terms.html`, `public/privacy.html`, `public/legal.css`는 운영 전 검토용 법률 문서를 독립 주소로 제공한다.
- 기존 `game-projects.mjs`를 프로젝트 공개 정보의 단일 기준으로 사용한다.

## 5. 단계별 동작

### 1단계: 운영 흔적 정리

- 공개 헤더에서 기기 선택기를 제거하고 `/device-preview.html`에만 유지한다.
- 상담 플러그인 키와 테스트 서비스 이름을 공개 HTML에서 제거한다.
- 상담 모듈은 명시적인 유효 키가 없으면 외부 스크립트를 생성하지 않는다.
- 푸터에서 임시 운영자 이름을 제거하고 현재 연도를 자동 표시한다.
- 미설정 Steam, itch.io와 Discord 링크는 비활성 안내 요소로 바꾼다.

### 2단계: 히어로 이동 흐름

- `게임 둘러보기`와 `최신 개발 소식` 링크를 제공한다.
- 전체 프로젝트 수, 대표 프로젝트 수와 개발 뉴스 수를 검증된 로컬 데이터로 표시한다.

### 3단계: 스튜디오 소개

- 확인 가능한 범위의 개발 방향, 공개 원칙과 현재 운영 상태를 설명한다.
- 출시 실적이나 구성원 정보를 추측하지 않는다.

### 4단계: 프로젝트 현황판

- 개발 중, 기획과 보류 프로젝트 수를 `GAME_PROJECTS`에서 계산한다.
- 출시일 대신 현재 공개 상태와 일정 미확정 원칙을 안내한다.

### 5단계: 로컬 프로젝트 보관함

- 즐겨찾기와 최근 본 프로젝트는 `localStorage`에 프로젝트 식별자만 저장한다.
- 손상된 JSON, 중복값과 존재하지 않는 식별자는 제거한다.
- 최근 본 프로젝트는 최대 6개를 유지한다.
- 개인정보 설정 영역에서 로컬 프로젝트 기록을 삭제할 수 있다.

### 6단계: 준비 상태 개선

- 판매 준비 상품은 링크가 아닌 정보 카드로 유지한다.
- 굿즈와 커뮤니티에 실제 연결 전 제공 범위와 데이터 상태를 설명한다.
- 해시태그 복사 같은 외부 계정이 필요 없는 기능만 제공한다.

### 7단계: 법률 문서 접근

- 이용약관과 개인정보처리방침을 독립 HTML로 제공한다.
- 두 문서는 `운영 전 검토용 초안`으로 표시한다.
- 확인되지 않은 사업자 정보와 법적 근거는 확정 문구로 작성하지 않는다.

### 8단계: 모바일·접근성

- 본문 바로가기 링크를 제공한다.
- 주요 필터와 행동 버튼의 최소 높이를 44px로 맞춘다.
- 히어로 보조 문구의 대비를 높인다.
- 개인정보 설정 버튼이 다른 고정 버튼 공간을 예약하지 않게 한다.
- 키보드 포커스 표시와 모션 축소 설정을 유지한다.

### 9단계: 검증

- `node --test tests/*.test.mjs`
- `pnpm exec tsc --noEmit --incremental false`
- `pnpm build`
- 메인, 약관과 개인정보 페이지 HTTP 200 확인
- PC 1440×900, 태블릿 1024×768, 모바일 390×844 확인

## 6. 오류 처리

- 저장소 접근이 거부되거나 실패하면 페이지 기능은 계속 동작하고 로컬 보관함만 빈 상태로 표시한다.
- 상담 키가 없거나 UUID 형식이 아니면 외부 상담 스크립트를 불러오지 않는다.
- 즐겨찾기와 최근 기록의 알 수 없는 프로젝트는 화면에 표시하지 않는다.
- 클립보드 사용이 실패하면 해시태그를 직접 복사할 수 있는 텍스트를 유지한다.

## 7. 완료 조건

- 공개 메인 페이지에 개발용 기기 선택기, 테스트 상담 이름과 하드코딩 상담 키가 없다.
- 메인 페이지에서 게임, 개발 뉴스, 스튜디오 소개, 프로젝트 현황, 로컬 보관함과 FAQ에 접근한다.
- 즐겨찾기와 최근 본 프로젝트가 안전하게 저장되고 삭제된다.
- 법률 초안 문서가 독립 주소로 열린다.
- 모바일 핵심 조작 영역이 44px 이상이다.
- 전체 테스트, 타입 검사와 운영 빌드가 통과한다.
