# DEVFORGE 공통 접근성·키보드 조작 보강 설계

---
## 목적

외부 서비스 없이 실행되는 DEVFORGE 공통 홈페이지와 Next.js 화면에서 키보드 사용자와 보조 기술 사용자가 대화상자, 개인정보 선택, 입력 오류와 동적 상태를 예측 가능하게 조작하도록 개선한다.

35개 개별 게임 페이지의 전용 인터랙션은 이번 범위에서 제외한다. 공통 홈페이지와 Next.js 화면의 기존 디자인·데이터 흐름·외부 연동 계약은 유지한다.

---
## 성공 기준

- 메인 페이지의 게임·문의·약관·개인정보 모달이 올바른 대화상자 역할과 제목 연결을 제공한다.
- 공통 모달은 열림 직후 내부 조작 요소로 초점을 이동하고 닫힌 뒤 실행 요소로 초점을 복원한다.
- 공통 모달은 `Escape`, 배경 클릭과 닫기 버튼으로 닫히며 `Tab`과 `Shift+Tab` 초점을 내부에서 순환한다.
- 모달이 열린 동안 배경 스크롤을 잠그고 동시에 두 개 이상의 모달을 열지 않는다.
- 네이티브 `<dialog>`를 사용하는 굿즈·개발 뉴스·커뮤니티 문의창도 같은 초점 복원 계약을 따른다.
- 개인정보 선택 패널은 제목과 설명이 연결되고 설정 버튼으로 다시 열었을 때 실제 초점 대상으로 이동한다.
- Next.js 로그인·관리자·성인 확인 입력은 오류 문구와 연결되고 오류 상태와 제출 중 상태를 보조 기술에 전달한다.
- 기존 모바일 메뉴, 검색·필터, 댓글, 데이터 상태와 공개 화면 동작에 회귀가 없다.

---
## 구현 방식

`public/dialog-accessibility.mjs`를 공통 대화상자 제어 모듈로 추가한다. 이 모듈은 `[data-dialog]`, `[data-dialog-open]`, `[data-dialog-close]` 계약을 사용하고, 사용자 정의 오버레이와 네이티브 `<dialog>`를 같은 공개 함수로 제어한다.

모듈은 각 대화상자를 열게 한 요소를 저장한다. 열 때 기존 대화상자를 먼저 닫고 내부의 첫 조작 요소로 초점을 옮긴다. 닫을 때 저장한 요소가 문서에 남아 있으면 초점을 복원한다. 사용자 정의 오버레이는 `role="dialog"`, `aria-modal="true"`, `aria-labelledby`와 `hidden` 상태를 동기화한다.

키보드 처리기는 현재 열린 대화상자에만 적용한다. `Escape`는 현재 창을 닫고, `Tab`은 첫 요소와 마지막 요소 사이에서 순환한다. 초점 가능한 요소가 없으면 대화상자 본체가 `tabindex="-1"`로 초점을 받는다.

메인 페이지의 인라인 열기·닫기 코드는 데이터 속성과 공통 제어기로 교체한다. 게임 카드가 동적 내용을 채운 뒤 공통 제어기의 `open` 함수를 호출하는 전역 연결점은 한 곳만 제공한다. 약관과 개인정보의 독립 페이지 링크는 그대로 유지한다.

굿즈·개발 뉴스·커뮤니티는 기존 네이티브 `<dialog>`와 스타일을 유지한다. 공통 모듈이 `showModal`, `close`와 `close` 이벤트를 연결하고, 지원하지 않는 환경에서는 `open` 속성을 동기화한다.

---
## 개인정보 선택 패널

개인정보 선택 패널은 페이지 탐색을 차단하지 않는 비모달 대화상자로 유지한다. 제목뿐 아니라 설명에도 고유 식별자를 부여하고 `aria-describedby`로 연결한다. 패널 본체는 `tabindex="-1"`을 가져 설정 버튼으로 다시 열 때 안정적으로 초점을 받는다.

선택 저장 뒤 패널을 닫고 개인정보 설정 버튼으로 초점을 복원한다. 결과 문구는 기존 `aria-live="polite"` 계약을 유지한다. 첫 방문의 자동 표시는 사용자의 현재 초점을 강제로 빼앗지 않는다.

---
## Next.js 입력 화면

로그인, 관리자 로그인과 성인 확인 폼은 제출 상태를 `aria-busy`로 제공한다. 서버 또는 클라이언트 검증 오류가 있으면 관련 입력에 `aria-invalid="true"`와 오류 문구의 식별자를 `aria-describedby`로 연결한다.

뉴스·상품 관리자 편집기는 서버 액션이 반환한 오류를 폼 수준 경고로 유지하되, 저장 중 상태를 폼에 전달한다. 개별 필드 오류 구조가 없는 현재 계약에서는 임의의 필드를 잘못된 입력으로 추정하지 않는다.

댓글의 반응 버튼과 기존 `role="alert"`, `aria-live`, `aria-pressed` 계약은 유지한다.

---
## 오류와 안전 동작

- 대화상자 또는 실행 요소가 없어도 초기화는 오류 없이 종료한다.
- 닫기 직전 실행 요소가 제거됐으면 초점 복원을 생략한다.
- 초점 가능한 요소가 없으면 대화상자 본체를 대체 초점 대상으로 사용한다.
- 네이티브 `<dialog>` API가 없으면 `open` 속성과 접근성 상태로 대체한다.
- 중복 초기화는 기존 제어기를 반환하고 이벤트 처리기를 추가하지 않는다.
- 파괴 함수는 등록된 이벤트, 스크롤 잠금과 전역 제어기 참조를 정리한다.

## 테스트 전략

- 공통 대화상자 단위 테스트: 열기, 단일 활성 창, Escape, 배경 클릭, 닫기 버튼, Tab 순환, 초점 복귀와 중복 초기화
- 정적 계약 테스트: 메인 모달의 역할·제목·데이터 속성, 공통 페이지 모듈 연결과 인라인 열기 코드 제거
- 개인정보 테스트: 제목·설명 연결, 설정 재개방 초점과 선택 뒤 복귀
- Next.js 테스트: 입력 오류 연결, `aria-invalid`, `aria-describedby`, `aria-busy`
- 회귀 검사: 모바일 메뉴, 반응형 통합, 개인정보 동의와 관련 페이지 테스트
- 전체 검사: `pnpm check`
