# DEVFORGE 성인 콘텐츠 접근 제한 설계

---

## 목표

프로젝트 H, U, V를 개발용 성인 확인 대상으로 지정한다. 인증되지 않은 방문자에게는 메인과 커뮤니티에서 실제 대표 이미지를 보내지 않고 모자이크 대체 화면을 표시한다. 상세 주소나 원본 이미지 주소로 직접 접근해도 서버가 먼저 인증 상태를 확인하여 콘텐츠 전달을 차단한다.

현재 단계의 인증은 사용자가 입력한 생년월일을 기준으로 하는 자기 확인 방식이다. PASS나 본인확인기관을 이용한 실제 본인인증으로 표시하지 않는다.

---

## 적용 대상

- 프로젝트 H: `/project_h/:path*`
- 프로젝트 U: `/project_u/:path*`
- 프로젝트 V: `/project_v/:path*`
- 대표 원본 이미지: `/images/games/project-h.png`, `/images/games/project-u.png`, `/images/games/project-v.png`
- 메인 게임 카드의 프로젝트 H, U, V
- 커뮤니티 게임 선택의 프로젝트 H, U, V

대상 목록은 `lib/age-gate/config.ts` 한곳에서 관리한다. 화면과 서버가 서로 다른 목록을 사용하지 않도록 식별자, 상세 경로, 대표 이미지 경로를 같은 설정에서 파생한다.

---

## 인증 흐름

1. 인증되지 않은 방문자는 메인과 커뮤니티에서 모자이크 대체 이미지만 확인한다.
2. 방문자가 성인 게임 카드를 선택하면 원래 상세 주소로 이동을 시도한다.
3. 서버 프록시가 인증 쿠키를 검사한다.
4. 쿠키가 없거나 위조되었거나 만료되었다면 `/age-verification?returnTo={원래주소}`로 이동시킨다.
5. 방문자가 생년월일과 개발용 자기 확인 문구에 동의한다.
6. 서버가 현재 날짜를 기준으로 만 19세 이상인지 계산한다.
7. 통과하면 12시간 유효한 서명 쿠키를 발급하고 허용된 원래 주소로 이동시킨다.
8. 인증 후 메인과 커뮤니티는 상태 API를 확인하고 성인 게임의 실제 대표 이미지를 표시한다.

인증된 상세 응답과 원본 이미지에는 `Cache-Control: private, no-store`를 적용해 인증 만료 후 브라우저 캐시에 내용이 남아 재사용되는 것을 막는다.

---

## 서버 구성

---

### 성인 콘텐츠 설정

`lib/age-gate/config.ts`에서 다음 정보를 관리한다.

- 성인 게임 식별자
- 보호할 프로젝트 폴더 경로
- 보호할 대표 이미지 경로
- 안전한 복귀 주소 판정

복귀 주소는 사이트 내부의 `/`로 시작하는 단일 경로만 허용하고 `//`, 외부 프로토콜, 제어 문자를 거부한다.

---

### 서명 쿠키

쿠키 이름은 `devforge_age_verified`를 사용한다. 값에는 버전과 만료 시각을 넣고 HMAC-SHA-256으로 서명한다.

- `HttpOnly`
- `SameSite=Lax`
- 전체 사이트 경로 적용
- 12시간 만료
- 운영 환경에서 `Secure`

서명 키는 `AGE_GATE_SECRET` 환경 변수에서만 읽는다. 개발 환경에서는 로컬 확인을 위한 개발 전용 키를 사용할 수 있지만, 운영 환경에서 키가 없으면 인증 발급과 보호 콘텐츠 접근을 모두 차단한다.

---

### 인증 API

`POST /api/age/verify`는 생년월일과 복귀 주소를 받는다.

- 날짜 형식과 실제 존재하는 날짜 검사
- 미래 날짜 거부
- 현재 날짜 기준 만 19세 계산
- 미성년 요청에 403 응답
- 잘못된 복귀 주소를 `/main.html#games`로 보정
- 통과 시 서명된 인증 쿠키 발급

`GET /api/age/status`는 현재 쿠키 검증 결과만 `{ verified: boolean }`로 반환한다. 생년월일은 저장하거나 응답하지 않는다.

---

### 서버 프록시

기존 관리자 프록시 범위에 성인 프로젝트 폴더와 원본 대표 이미지 경로를 추가한다.

- 인증 성공: 보호 콘텐츠 전달과 `private, no-store` 적용
- 인증 없음: 성인 확인 페이지로 이동
- 쿠키 위조 또는 만료: 인증 없음과 동일하게 처리
- 운영 서명 키 누락: 실패 닫힘 방식으로 접근 차단

관리자 로그인 세션 갱신 기능은 기존 동작을 유지한다.

---

## 화면 구성

---

### 메인 게임 카드

프로젝트 H, U, V의 초기 HTML에는 실제 대표 이미지 주소를 넣지 않는다. 공통 모자이크 SVG를 사용하고 원본 주소는 `data-adult-image` 속성에 저장한다.

- 이미지 전체 픽셀 모자이크 표현
- 중앙 `19+` 표시
- `성인 확인 후 열람` 안내
- 카드 전체와 상세 버튼 모두 같은 보호 주소 사용
- 인증 상태 API가 성공한 경우에만 원본 이미지 주소 적용

`data-adult-image`는 주소 정보만 제공하므로 원본 요청 자체는 서버 프록시가 다시 검사한다.

---

### 성인 확인 페이지

기존 DEVFORGE 색상과 헤더 분위기를 유지하되 실제 성인 게임 이미지는 배경으로 사용하지 않는다.

- `19+ 성인 콘텐츠` 제목
- 개발용 자기 확인 방식 안내
- 생년월일 입력
- 만 19세 이상 자기 확인 체크
- 확인 버튼
- 메인 게임 목록으로 돌아가기
- 미성년, 잘못된 날짜, 서버 설정 오류 안내

이 페이지는 실제 본인인증으로 오해할 수 있는 문구를 사용하지 않는다.

---

### 커뮤니티 페이지

프로젝트 H, U, V를 선택했을 때 인증 전에는 모든 플랫폼 시연 카드와 대표 콘텐츠에 모자이크 대체 이미지를 사용한다. 인증 상태가 확인된 뒤에만 실제 프로젝트 대표 이미지로 교체한다.

---

## 데이터와 개인정보

- 생년월일은 나이 계산에만 사용
- 데이터베이스 저장 없음
- 로그와 쿠키에 생년월일 저장 없음
- 쿠키에는 인증 버전과 만료 시각만 포함
- 사용자 계정과 연결하지 않음

---

## 오류 처리

- 잘못된 날짜: 입력 화면에 오류 표시
- 만 19세 미만: 접근 불가 안내와 메인 복귀 제공
- 만료·위조 쿠키: 재인증 화면으로 이동
- 인증 상태 API 실패: 모자이크 유지
- 운영 서명 키 누락: 인증 발급 중단과 설정 오류 표시
- 허용되지 않은 복귀 주소: 메인 게임 영역으로 이동

모든 오류는 실제 보호 콘텐츠를 먼저 표시하지 않는 실패 닫힘 방식을 사용한다.

---

## 배포 제약

서버 프록시가 실행되지 않는 순수 정적 호스팅에서는 직접 파일 주소를 보호할 수 없다. 성인 콘텐츠 보호 기능이 적용된 사이트는 Next.js 서버 또는 동일한 서버 측 요청 검사가 가능한 환경으로 배포해야 한다.

실제 출시 전에는 개발용 자기 확인을 PASS 또는 본인확인기관 연동으로 교체하고 관련 법률·플랫폼 정책 검토가 필요하다.

---

## 검증 기준

- 인증 전 메인 카드에 실제 H, U, V 이미지 주소가 없음
- 인증 전 커뮤니티 성인 게임 선택 시 모자이크 유지
- 상세 HTML 직접 접근 시 성인 확인 페이지로 이동
- 프로젝트 내부 자료와 원본 대표 이미지 직접 접근 차단
- 올바른 성인 생년월일만 인증 쿠키 발급
- 미성년과 잘못된 날짜 거부
- 쿠키 위조와 12시간 만료 거부
- 인증 후 원래 상세 주소 복귀
- 인증 후 보호 콘텐츠 응답에 `private, no-store` 존재
- 기존 관리자 프록시와 전체 자동 테스트 유지
- TypeScript 검사와 배포 빌드 통과
