# DEVFORGE 관리자 상품·재고 관리 설계

---

## 목적

DEVFORGE 관리자가 기존 관리자 계정으로 상품을 등록·수정·삭제하고, 공개 메인 화면의 굿즈 목록과 재고 상태를 관리할 수 있게 한다. 판매처가 정해지지 않은 현재는 재고를 직접 입력하며, 향후 외부 판매처의 공식 API를 연결할 수 있는 경계를 미리 둔다.

---

## 구현 범위

- 기존 Supabase 관리자 인증 재사용
- 관리자 상품 목록·등록·수정·삭제
- 상품 대표 이미지 업로드와 교체
- 공개·비공개 및 판매 상태 관리
- 수동 재고 입력
- 공개 메인 화면의 동적 상품 표시
- 굿즈 전용 `public/goods.html` 페이지
- 메인 헤더와 굿즈 미리보기의 전용 페이지 연결
- 판매 주소 유무와 재고에 따른 구매 버튼 변경
- 외부 판매처 재고 어댑터 인터페이스
- 기존 여덟 개 임시 상품용 통일된 목업 이미지 생성
- Supabase 미설정 환경의 정적 상품 대체 화면 유지

장바구니, 사이트 내부 결제, 주문·배송 관리, 외부 판매처 실제 API 호출은 이번 범위에서 제외한다. 외부 판매처가 결정되고 공식 API 사용 권한과 인증 정보가 준비된 뒤 별도 단계로 연결한다.

---

## 기술 구성

- 관리자와 공개 화면: 기존 Next.js 16 프로젝트
- 인증: 기존 Supabase Auth 관리자 계정
- 상품 저장: Supabase Postgres `products` 테이블
- 이미지 저장: Supabase Storage `product-images` 버킷
- 공개 상품 조회: Next.js `/api/products` 엔드포인트
- 정적 공개 화면 연결: `public/main.html`의 브라우저 스크립트
- 굿즈 전용 화면: `public/goods.html`, `public/goods.css`, `public/goods.mjs`
- 향후 재고 공급자: 서버 전용 `StockProvider` 인터페이스

Supabase 프로젝트가 없는 현재는 화면, 코드, 마이그레이션 SQL, 이미지 자산과 자동 테스트까지 구현한다. 원격 상품 저장과 이미지 업로드는 Supabase 프로젝트 연결 뒤 검증한다.

## 상품 데이터 구조

### `products`

- `id`: 상품 UUID
- `name`: 상품명
- `category`: 상품 분류
- `game_name`: 관련 게임 또는 브랜드명
- `price`: 현재 판매가
- `original_price`: 할인 전 가격 또는 빈 값
- `badge`: `new`, `hot`, `limited`, `none`
- `description`: 짧은 상품 설명
- `image_path`: Storage 내부 이미지 경로
- `sales_url`: 외부 판매 페이지 주소 또는 빈 값
- `stock_mode`: `manual` 또는 `external`
- `stock_quantity`: 현재 재고 수량
- `external_provider`: 향후 판매처 식별자 또는 빈 값
- `external_product_id`: 향후 판매처 상품 식별자 또는 빈 값
- `publication_status`: `published` 또는 `hidden`
- `display_order`: 공개 화면 노출 순서
- `created_at`: 생성 시각
- `updated_at`: 수정 시각

가격과 재고는 0 이상의 정수만 허용한다. 할인 전 가격이 입력된 경우 현재 판매가보다 커야 한다. 판매 주소는 `https://` 주소만 허용한다.

## 상품 상태와 디자인

공개 카드의 상태는 저장값과 재고를 조합하여 계산한다.

| 상태 | 조건 | 카드 표시 | 버튼 |
|---|---|---|---|
| 판매 중 | 공개, 주소 있음, 재고 6개 이상 | 청록색 재고 표시 | `구매하기` 활성 |
| 재고 부족 | 공개, 주소 있음, 재고 1~5개 | 주황색 `재고 N개` 배지 | `구매하기` 활성 |
| 품절 | 공개, 재고 0개 | 흐린 이미지와 붉은색 `품절` 배지 | `품절` 비활성 |
| 판매 준비 중 | 공개, 판매 주소 없음 | 보라색 `판매 준비 중` 배지 | `준비 중` 비활성 |
| 비공개 | `publication_status = hidden` | 공개 화면에서 미표시 | 관리자 화면에만 표시 |

관리자 목록에서는 모든 상태를 텍스트와 색상으로 함께 표시하여 색상만으로 상태를 구별하지 않도록 한다. 관리자 입력 화면에는 재고 수량과 판매 주소에 따라 계산될 공개 상태 미리보기를 제공한다.

---

## 관리자 화면

### 상품 목록 `/admin/products`

- 상품 이미지, 이름, 가격, 재고, 공개 상태, 판매 상태 표시
- 수정 화면 이동
- 삭제 확인 후 상품과 저장 이미지 삭제
- 등록 완료, 수정 완료, 삭제 완료 메시지 표시

### 상품 등록 `/admin/products/new`

- 상품명, 분류, 관련 게임, 설명 입력
- 판매가와 할인 전 가격 입력
- 재고 수량과 재고 방식 입력
- 배지와 공개 상태 선택
- 대표 이미지 업로드
- 판매 주소와 향후 외부 상품 식별자 입력
- 공개 상태 미리보기

### 상품 수정 `/admin/products/[id]/edit`

- 기존 값을 불러와 수정
- 새 이미지가 없으면 기존 이미지 유지
- 새 이미지가 있으면 저장 성공 후 기존 이미지 삭제

관리자 공통 메뉴에는 `글 관리`, `새 글`, `상품 관리`, `새 상품`, `공개 사이트`, `로그아웃`을 표시한다.

## 공개 굿즈 화면

### 메인 화면

`public/main.html`의 기존 굿즈 디자인을 유지하면서 공개 상품을 `/api/products`에서 불러온다. API 성공 시 데이터베이스 상품 중 노출 순서가 빠른 상품을 미리보기로 표시하고, API가 설정되지 않았거나 조회에 실패하면 기존 정적 상품을 그대로 표시한다.

메인 헤더의 `굿즈` 메뉴는 페이지 내부 위치가 아닌 `goods.html`로 이동한다. 굿즈 섹션 제목 오른쪽에도 개발 뉴스와 같은 형태의 `더보기` 버튼을 두어 전체 상품 페이지로 이동하게 한다.

### 굿즈 전용 페이지

`public/goods.html`은 개발 뉴스 페이지와 동일한 DEVFORGE 공통 헤더를 사용하고, 선택 상태인 `굿즈` 메뉴를 강조한다. 페이지 상단에는 굿즈 소개 제목과 짧은 안내를 표시하고, 본문에는 공개 상품 전체를 노출 순서대로 보여준다.

전용 페이지는 공개 상품이 없을 때의 빈 상태, 상품 조회 실패 안내와 Supabase 미설정 상태의 임시 상품 대체 화면을 제공한다. 메인 화면과 전용 페이지는 같은 상품 카드 생성 모듈을 사용하여 가격과 재고 상태가 서로 다르게 표시되지 않도록 한다.

상품 카드는 이미지, 배지, 분류, 이름, 관련 게임, 가격, 할인 전 가격, 재고 상태와 버튼을 표시한다. 판매 주소가 있는 판매 중 상품만 새 창으로 외부 판매처를 연다. 비활성 버튼은 링크로 동작하지 않으며 키보드와 화면 읽기 도구에서도 상태를 알 수 있어야 한다.

## 임시 상품 이미지

현재 여덟 개 상품마다 1장의 통일된 상품 목업 이미지를 생성한다.

- 아비스 크로니클 주인공 키링
- 네온 펄스 후드집업
- 루나 점프 아트 포스터 세트
- DEVFORGE 로고 머그컵
- 전 게임 캐릭터 스티커팩
- 에코 보이드 대형 마우스패드
- 아비스 크로니클 핀뱃지 3종 세트
- 네온 펄스 OST 한정판 CD

이미지는 어두운 배경, 청록·보라 네온 조명, 중앙 제품 구도, 글자와 워터마크가 없는 전자상거래용 목업으로 통일한다. 파일은 `public/images/goods/`에 저장한다. 생성 이미지는 임시 목업임을 관리자 설명과 문서에 명시하고 실제 판매 전 실물 사진으로 교체한다.

## 인증과 보안

- 모든 상품 변경 작업에서 기존 `requireAdmin` 서버 검증 사용
- Supabase Row Level Security에서 공개 상품 읽기만 익명 허용
- 비공개 상품 읽기와 작성·수정·삭제는 관리자 역할만 허용
- 서비스 역할 키와 외부 판매처 인증 정보는 브라우저에 포함하지 않음
- 외부 판매처 API 호출은 서버에서만 수행
- 판매 주소는 저장 전 `https://` 형식 검증
- 이미지 형식은 JPG, PNG, WebP로 제한
- 이미지 크기는 5MB 이하로 제한

외부 판매 페이지 HTML을 직접 수집하는 스크래핑은 차단, 구조 변경, 이용 조건 문제와 잘못된 재고 표시 위험 때문에 사용하지 않는다.

---

## 재고 연동 경계

`StockProvider`는 외부 상품 식별자를 받아 재고 수량과 조회 시각을 반환한다. 이번 구현의 `ManualStockProvider`는 데이터베이스의 `stock_quantity`를 그대로 사용한다. 향후 판매처가 결정되면 해당 공식 API용 공급자를 추가하고 상품의 `stock_mode`를 `external`로 변경한다.

외부 API가 실패하거나 오래된 값을 반환하면 마지막 정상 재고를 표시하되 `재고 확인 중` 상태로 구매 버튼을 비활성화한다. 정확한 동기화 주기와 오류 정책은 판매처 API 제한이 확인된 뒤 확정한다.

---

## 오류 처리

- Supabase 미설정: 관리자 설정 안내와 기존 정적 굿즈 유지
- 입력 오류: 필드별 한글 오류 표시
- 이미지 업로드 오류: 형식, 크기, 저장 실패 구분
- 상품 저장 오류: 입력 내용 유지와 일반화된 오류 안내
- 공개 조회 오류: 기존 정적 굿즈 유지
- 삭제 오류: 상품을 유지하고 실패 안내
- 재고 API 오류: 마지막 정상값 또는 `재고 확인 중` 표시

오류 메시지에는 데이터베이스 세부 정보, 인증 토큰, 외부 API 키를 포함하지 않는다.

---

## 검증 기준

- 미로그인 사용자가 상품 관리자 화면에 접근할 수 없음
- 관리자 역할이 없는 계정이 상품을 변경할 수 없음
- 필수 입력값과 가격·재고·주소 검증이 동작함
- 공개 상품만 공개 API와 메인 화면에 표시됨
- 메인 헤더의 굿즈 메뉴와 섹션 더보기 버튼이 `goods.html`로 이동함
- 굿즈 전용 페이지가 공통 헤더와 공개 상품 전체를 표시함
- 메인과 굿즈 전용 페이지가 동일한 상품 상태 계산과 카드 표현을 사용함
- 다섯 가지 상태가 조건에 맞는 디자인과 버튼으로 표시됨
- 품절과 준비 중 상품에서 외부 이동이 발생하지 않음
- 상품 이미지 업로드·교체·삭제 흐름이 안전하게 처리됨
- Supabase 미설정 또는 조회 실패 시 기존 정적 상품이 유지됨
- 여덟 개 임시 목업 이미지가 각 상품 카드에 표시됨
- 모바일과 데스크톱에서 관리자 화면과 상품 카드가 정상 표시됨
- 전체 자동 테스트, TypeScript 검사와 프로덕션 빌드가 통과함

Supabase 프로젝트와 실제 판매처가 없는 상태에서는 원격 저장, 실제 외부 재고 동기화와 실물 이미지 정확성을 완료로 판정하지 않는다.
