# 플레이풀 랩 공통 디자인 시스템 설계

---
## 1. 결론

메인 페이지와 공용·운영 페이지에 흰색 중심의 `플레이풀 랩` 디자인을 적용한다. 미술·게임·기계의 인상을 민트, 바이올렛, 오렌지 세 가지 강조색으로 균형 있게 표현하고, 개별 프로젝트 페이지의 기존 디자인은 변경하지 않는다.

공통 디자인은 `public/playful-lab-theme.css` 한 파일을 기준으로 관리한다. 적용 대상 페이지에만 테마 식별자를 추가하고 기존 스타일 다음에 공통 파일을 불러와, 기능과 데이터 구조를 유지하면서 시각 표현만 통일한다.

---
## 2. 목표

- 흰색 계열 배경과 밝은 표면을 사용한 일관된 사이트 인상
- 미술의 자유로움, 게임의 생동감, 기계의 정밀함을 한 체계 안에서 표현
- 메인, 콘텐츠, 로그인·성인 인증·관리자 화면의 공통 구성 요소 통일
- 기존 링크, 필터, 캐러셀, 로그인, 관리자 기능, 뉴스·상품·게임 데이터 보존
- 모바일부터 넓은 데스크톱까지 읽기 쉽고 안정적인 반응형 화면 제공
- 개별 프로젝트 페이지와 개발 도구 화면에 대한 의도치 않은 스타일 전파 방지

---
## 3. 적용 범위

---
### 포함 대상

- 정적 공개 페이지: `public/main.html`, `public/goods.html`, `public/devlog.html`, `public/community.html`, `public/terms.html`, `public/privacy.html`
- Next.js 공용 화면: 회원 로그인, 회원 관련 화면, 성인 인증, 뉴스 상세와 댓글
- Next.js 운영 화면: 관리자 로그인, 뉴스 관리, 상품 관리
- 대상 화면에서 공유하는 헤더, 내비게이션, 푸터, 모달, 알림, 폼, 카드, 상태 표시

---
### 제외 대상

- `public/project_*.html` 형식의 모든 개별 프로젝트 페이지
- 개별 프로젝트가 사용하는 전용 CSS, 이미지, 스크립트
- `public/device-preview.html` 개발용 미리보기 도구
- 데이터 구조, API, 인증 정책, 관리자 권한, 저장 방식의 변경
- 콘텐츠 문구, 상품·뉴스·게임 데이터, 프로젝트 대표 이미지의 교체

개발용 미리보기 도구는 방문자용 화면이 아니며 자체적인 장치 프레임 표현이 목적이므로 공통 테마 적용 대상에서 제외한다.

---
## 4. 시각 원칙

---
### 전체 인상

화면의 대부분은 흰색과 매우 옅은 청회색으로 유지한다. 강조색은 넓은 면을 채우기보다 버튼, 배지, 선택 상태, 장식 선, 작은 그래픽 요소에 사용한다. 이렇게 구성해 세 가지 개성이 함께 보여도 내용의 가독성이 먼저 유지되도록 한다.

---
### 세 가지 상징

- 미술: 유연한 곡선, 비대칭 장식, 민트 색상
- 게임: 또렷한 선택 상태, 반응형 움직임, 바이올렛 색상
- 기계: 정돈된 격자, 얇은 경계선, 오렌지 상태 강조

장식은 콘텐츠를 가리거나 버튼으로 오해되지 않도록 비상호작용 요소로 제한한다.

---
## 5. 공통 디자인 토큰

| 용도 | 값 | 적용 기준 |
|---|---:|---|
| 기본 배경 | `#FFFFFF` | 페이지 전체 바탕 |
| 보조 배경 | `#F7FBFF` | 구역 분리와 넓은 패널 |
| 카드 배경 | `#EEF3F8` | 카드, 입력 그룹, 빈 상태 |
| 주요 글자 | `#172A49` | 제목, 본문, 기본 아이콘 |
| 보조 글자 | `#53677E` | 설명, 날짜, 보조 정보 |
| 경계선 | `#DCE7F0` | 카드, 입력창, 구분선 |
| 미술 강조 | `#43D7C3` | 브랜드 장식, 긍정 상태, 주요 포인트 |
| 게임 강조 | `#7768F8` | 선택 상태, 콘텐츠 이동, 핵심 버튼 |
| 기계 강조 | `#FF9256` | 경고, 운영 상태, 보조 행동 |
| 오류 | `#D94B64` | 오류 메시지와 실패 상태 |
| 성공 | `#218A76` | 완료 메시지와 정상 상태 |

색상 외에도 여백, 둥근 모서리, 그림자, 글자 크기, 전환 시간을 공통 변수로 정의한다. 모든 구성 요소는 직접 입력한 임의 값보다 이 토큰을 우선 사용한다.

---
## 6. 적용 구조

---
### 공통 파일

`public/playful-lab-theme.css`를 시각 규칙의 단일 기준으로 사용한다. 정적 HTML은 기존 CSS 다음에 이 파일을 연결한다. Next.js는 루트 레이아웃에서 공개 정적 파일을 연결해 로그인, 인증, 뉴스, 관리자 화면이 같은 규칙을 사용하도록 한다.

---
### 범위 제한

적용 대상의 `body`에 `data-theme="playful-lab"` 식별자를 둔다. 공통 CSS의 모든 규칙은 이 식별자 아래로 제한한다. 개별 프로젝트 페이지와 개발용 미리보기에는 식별자와 공통 CSS 연결을 모두 추가하지 않는다.

이중 제한으로 공통 테마가 프로젝트 전용 스타일에 우연히 영향을 주는 상황을 방지한다.

---
### 기존 CSS와의 관계

기존 CSS는 레이아웃과 동작의 기반으로 유지한다. 공통 테마는 나중에 로드되어 색상, 표면, 타이포그래피, 경계선, 그림자, 상태 표현을 덮어쓴다. 기존 규칙과 충돌하는 경우 공통 테마 내부의 범위 선택자를 조정하며, 전역 강제 우선순위 사용은 최소화한다.

---
## 7. 공통 구성 요소

---
### 헤더와 내비게이션

- 흰색 반투명 표면과 얇은 청회색 경계선
- 현재 페이지는 바이올렛 또는 민트 밑줄과 명확한 글자 대비로 표시
- 모바일 메뉴는 같은 색상과 간격 규칙 사용
- 키보드 초점은 두께가 충분한 바이올렛 외곽선으로 표시

---
### 버튼과 입력창

- 주요 버튼: 바이올렛 중심, 흰색 글자, 민트 보조 반응
- 보조 버튼: 흰색 표면, 남색 글자, 청회색 경계선
- 경고·운영 버튼: 오렌지 강조, 의미가 필요한 곳에만 사용
- 입력창: 흰색 표면, 명확한 레이블, 오류 시 색상과 문구를 함께 표시

---
### 카드와 패널

- 흰색 또는 옅은 청회색 표면
- 얇은 경계선과 낮은 그림자
- 카드 간격과 둥근 모서리 크기 통일
- 마우스 올림 효과는 이동 가능한 카드에만 적용

---
### 배지와 상태

- 민트: 정상, 공개, 완료
- 바이올렛: 선택, 진행, 주요 분류
- 오렌지: 확인 필요, 제한, 운영 주의
- 빨강: 실패, 삭제, 오류

색상만으로 의미를 구분하지 않고 텍스트 또는 아이콘을 함께 제공한다.

---
### 모달과 알림

- 배경과 본문의 명확한 층 분리
- 제목, 설명, 주요 행동, 취소 행동 순서 통일
- 성공·오류 알림은 같은 위치와 여백 규칙 사용
- 닫기 버튼과 키보드 초점 경로 보장

---
## 8. 페이지군별 표현

---
### 브랜드 페이지

대상은 메인, 스튜디오·소개 성격의 구역, 자주 묻는 질문, 이용약관, 개인정보처리방침이다. 민트를 주요 강조색으로 사용하고 여백을 넉넉히 둔다. 메인 캐러셀의 이전·다음 버튼과 진행 게이지는 기존 동작을 유지하면서 공통 토큰으로 다시 표현한다.

---
### 콘텐츠 페이지

대상은 상품, 개발 소식, 커뮤니티, 뉴스 상세와 댓글이다. 바이올렛을 주요 강조색으로 사용한다. 카드, 필터, 목록, 페이지 이동, 댓글 계층의 구분을 명확히 하여 많은 정보도 빠르게 읽을 수 있게 한다.

---
### 운영 페이지

대상은 로그인, 회원 관련 화면, 성인 인증, 관리자 로그인, 뉴스 관리, 상품 관리다. 오렌지는 주의와 운영 상태를 나타내는 보조색으로만 사용한다. 폼 레이블, 권한 안내, 저장·삭제 결과, 빈 상태의 대비와 명확성을 우선한다.

모든 페이지군은 동일한 배경, 글자, 경계선, 여백, 버튼 규칙을 공유하며 강조색의 비중만 다르게 사용한다.

---
## 9. 기능과 데이터 보존

- 메인 캐러셀의 방향별 이동, 자동 전환, 진행 게이지 유지
- 캐챗 바로가기 `http://localhost:3001` 유지
- 내비게이션과 모든 내부 링크 대상 유지
- 상품 필터와 재고 상태 표시 유지
- 개발 소식 목록과 상세 이동 유지
- 로그인, 로그아웃, 성인 인증, 댓글, 관리자 기능 유지
- 뉴스·상품·게임 데이터와 이미지 경로 유지

테마 작업 중 기능 변경이 필요해 보이는 항목은 시각 결함과 분리해 기록한다. 이번 범위에서는 기능 코드를 함께 재설계하지 않는다.

---
## 10. 반응형과 접근성

- 검증 기준 너비: 모바일 `375px`, 태블릿 `768px`, 데스크톱 `1440px`
- 작은 화면에서는 여러 열을 한 열로 전환하고 주요 행동 순서를 유지
- 가로 넘침, 버튼 겹침, 잘린 문구, 고정 요소 충돌 방지
- 본문과 배경, 버튼과 글자의 대비 확보
- 키보드만으로 메뉴, 링크, 폼, 모달, 캐러셀 조작 가능
- 모든 상호작용 요소에 보이는 초점 상태 제공
- 동작 축소 환경에서는 장식 전환과 이동 효과 축소
- 상태 전달 시 색상과 텍스트를 함께 사용

---
## 11. 로딩·오류·빈 상태

- 로딩: 밝은 카드 표면과 낮은 대비의 골격 화면 사용
- 오류: 오류 색상, 짧은 원인 문구, 가능한 복구 행동 표시
- 빈 상태: 단순한 장식, 현재 상태 설명, 다음 행동 표시
- 권한 없음: 접근 불가 이유와 돌아갈 위치 표시
- 네트워크 실패: 기존 데이터를 임의로 대체하지 않고 재시도 가능한 상태 표시

운영 화면에서도 어두운 전용 오류 화면을 만들지 않고 공통 밝은 테마를 유지한다.

---
## 12. 구현 순서

1. 공통 토큰과 테마 범위 선택자 작성
2. 헤더, 내비게이션, 버튼, 입력창, 카드, 배지, 모달 스타일 작성
3. 메인 페이지와 공용 정적 페이지에 테마 연결
4. 로그인, 회원, 성인 인증, 뉴스 상세 화면에 테마 연결
5. 관리자 로그인, 뉴스 관리, 상품 관리 화면에 테마 연결
6. 프로젝트 페이지와 개발 도구의 비적용 상태 확인
7. 자동 검사, 타입 검사, 운영 빌드 실행
8. 모바일·태블릿·데스크톱 수동 화면 점검
9. 접근성, 콘솔 오류, 회귀 동작 최종 점검

---
## 13. 검증 방법

---
### 자동 검증

- 대상 정적 페이지에 테마 파일과 테마 식별자가 모두 존재하는지 검사
- 개별 프로젝트 페이지와 개발용 미리보기에 테마가 연결되지 않았는지 검사
- 기존 전체 테스트 실행
- TypeScript 타입 검사 실행
- Next.js 운영 빌드 실행

---
### 수동 검증

- `375px`, `768px`, `1440px` 화면에서 레이아웃 확인
- 메인 캐러셀의 왼쪽·오른쪽 방향, 자동 전환, 진행 게이지 확인
- 메뉴, 상품 필터, 뉴스 이동, 로그인, 성인 인증, 댓글, 관리자 폼 확인
- 키보드 탐색 순서와 초점 표시 확인
- 브라우저 콘솔 오류와 네트워크 경로 오류 확인
- 개별 프로젝트 페이지의 시각적 변경이 없는지 전후 비교

---
## 14. 완료 기준

- 모든 포함 대상에서 동일한 토큰과 공통 구성 요소가 사용됨
- 개별 프로젝트 페이지와 개발용 미리보기에 공통 테마가 적용되지 않음
- 기존 핵심 기능과 링크가 그대로 동작함
- 세 기준 너비에서 가로 넘침과 주요 요소 겹침이 없음
- 키보드 초점과 상태 문구가 확인 가능함
- 테스트, 타입 검사, 운영 빌드가 모두 통과함
- 브라우저 콘솔에 새 오류가 발생하지 않음

## 15. 위험과 대응

| 위험 | 대응 |
|---|---|
