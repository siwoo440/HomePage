# DEVFORGE 외부 서비스 연결 전 로컬 완성도 강화 설계

## 1. 목적

Supabase, YouTube, GA4, Vercel, 공식 도메인처럼 별도 계정이나 비용 가능성이 있는 서비스를 연결하기 전에 DEVFORGE 사이트의 공개 화면, 관리자 입력 화면, 회원·댓글 시연 흐름, 개인정보 보호 구조와 자동 검증 체계를 로컬 환경에서 완성한다.

기존 DEVFORGE의 디자인과 외부 서비스 연결 지점을 유지하고, 현재 구현을 다시 만드는 대신 검사에서 확인된 부족한 부분만 단계적으로 보강한다.

## 2. 사용자와 성공 기준

### 방문자

- PC, 태블릿과 모바일에서 주요 공개 페이지를 정상적으로 탐색한다.
- 키보드만으로 메뉴, 모달과 주요 조작 요소를 사용할 수 있다.
- 이미지나 외부 데이터가 없을 때도 안내 문구를 확인한다.
- 시연 데이터와 실제 운영 데이터를 혼동하지 않는다.

### 콘텐츠 관리자

- Supabase가 없는 로컬 환경에서도 뉴스와 상품 입력 규칙, 오류 메시지와 공개 결과 미리보기를 확인한다.
- 로컬 미리보기와 실제 저장 동작을 명확하게 구분한다.
- 개발용 기능으로 관리자 인증을 우회하지 않는다.

### 개발자

- 외부 계정 없이 전체 테스트, TypeScript 검사와 운영 빌드를 실행한다.
- 공개 페이지의 링크, 정적 자원, 반응형 구성과 키보드 동작을 재현 가능한 절차로 검사한다.
- 외부 서비스를 나중에 연결할 수 있도록 기존 어댑터와 환경 변수 계약을 유지한다.

## 3. 범위

### 포함

1. 공개 사이트 링크, 정적 자원, 반응형 화면과 접근성 점검
2. 뉴스·상품 입력 검증과 개발 환경 전용 결과 미리보기
3. 회원·댓글 시연 상태와 권한 규칙 보강
4. 개인정보처리방침·이용약관 초안과 기술 보안 검사
5. 전체 자동 테스트, 타입 검사, 운영 빌드와 수동 브라우저 검사

### 제외

- Supabase 프로젝트 생성과 실제 인증·저장 연결
- YouTube Data API 연결
- 실제 GA4 측정 ID 연결
- 실제 판매처 재고 연동
- Vercel 배포와 공식 도메인 구매·연결
- 법률 전문가의 최종 검토
- 기존 정적 HTML 전체의 Next.js 변환
- DEVFORGE 디자인 체계와 게임별 고유 연출의 전면 개편

## 4. 개발 원칙

### 점검 우선 보강

기존 기능을 기준선으로 기록한 뒤 실패 조건을 재현하고 필요한 부분만 수정한다. 관련 없는 파일 구조 개편이나 디자인 변경은 수행하지 않는다.

### 운영 기능과 개발 기능 분리

개발용 미리보기는 서버 전용 환경 변수 `DEVFORGE_LOCAL_PREVIEW=1`이 설정되고 `NODE_ENV !== "production"`일 때만 사용할 수 있다. 운영 환경에서는 환경 변수 값과 관계없이 개발용 미리보기 경로를 사용할 수 없어야 한다.

### 시연 상태 명시

임시 뉴스, 상품, 회원과 댓글은 화면에서 `시연 데이터`임을 표시한다. 시연 상태는 실제 저장 성공이나 실제 로그인으로 표현하지 않는다.

### 외부 서비스 계약 유지

Supabase, YouTube와 분석 기능의 인터페이스를 제거하지 않는다. 설정이 없는 상태의 안전한 대체 동작을 유지하고, 나중에 실제 설정을 등록했을 때 같은 인터페이스로 연결한다.

### 테스트 우선

각 변경은 실패 테스트, 최소 구현, 집중 테스트, 전체 회귀 검사 순서로 진행한다. 새 런타임 의존성은 추가하지 않는다.

## 5. 전체 구조

사이트는 다음 세 영역을 유지한다.

1. `public`의 정적 공개 페이지와 공통 브라우저 모듈
2. `app`의 Next.js 관리자·회원·뉴스 화면과 API 경로
3. `lib`의 입력 검증, 권한, 시연 데이터와 외부 서비스 어댑터

테스트는 화면 문자열만 확인하는 방식에 의존하지 않고, 가능한 동작을 담당하는 순수 함수와 공개 인터페이스를 직접 검사한다. 정적 페이지 연결과 자원 경로는 저장소 전체 검사로 보완한다.

## 6. 작업 영역 A: 공개 사이트 품질·접근성

### 대상

- `public/main.html`
- `public/goods.html`
- `public/devlog.html`
- `public/community.html`
- 공개 게임 페이지
- `public/responsive-nav.mjs`
- `public/responsive-shell.css`
- `public/device-preview.html`

### 동작

- 공개 HTML의 내부 링크와 정적 자원 경로를 저장소의 실제 파일과 대조한다.
- 해시 링크는 대상 페이지에 해당 식별자가 존재하는지 검사한다.
- 공통 메뉴는 홈, 게임, 굿즈, 개발 뉴스, 커뮤니티, 문의와 로그인 경로를 유지한다.
- 모바일 서랍 메뉴는 포커스 이동, 순환, 복귀, `Escape` 닫기와 화면 너비 변경 시 정리를 보장한다.
- 이미지나 API 데이터가 없을 때 대체 이미지와 안내 문구를 표시한다.
- 모바일 390×844, 태블릿 1024×768, PC 1440×900을 기본 수동 검사 크기로 사용한다.

### 완료 조건

- 주요 내부 링크와 정적 자원에 확인 가능한 누락이 없다.
- 세 기본 화면 크기에서 의도하지 않은 본문 가로 스크롤과 요소 겹침이 없다.
- 키보드만으로 메뉴와 모달을 열고 닫고 이동한다.
- 브라우저 콘솔에 처리되지 않은 오류가 없다.

## 7. 작업 영역 B: 관리자 입력과 로컬 미리보기

### 대상

- `app/admin/news/news-editor.tsx`
- `app/admin/products/product-editor.tsx`
- `lib/news/validation.ts`
- `lib/products/validation.ts`
- 관리자 관련 테스트

### 구성

입력 폼, 검증 함수, 결과 미리보기와 실제 저장 액션을 분리한다.

1. 입력 폼이 현재 값을 수집한다.
2. 공유 검증 함수가 필드별 오류 또는 정규화된 값을 반환한다.
3. 개발용 미리보기는 정규화된 값을 읽기 전용 카드로 표시한다.
4. 실제 저장 액션은 기존 Supabase 관리자 권한 검사를 계속 요구한다.

### 개발용 미리보기 안전 규칙

- 미리보기 기능은 서버 전용 환경 변수 `DEVFORGE_LOCAL_PREVIEW=1`과 `NODE_ENV !== "production"` 조건을 모두 만족해야 한다.
- 미리보기는 저장, 업로드, 삭제와 인증 우회를 수행하지 않는다.
- 운영 빌드에서는 개발 설정이 들어 있어도 미리보기 접근을 거부한다.
- 미리보기 화면에 `저장되지 않는 시연 화면` 안내를 표시한다.

### 검증 범위

- 뉴스 제목, 요약, 본문, 태그, 공개 상태와 이미지
- 상품명, 분류, 가격, 할인 전 가격, 설명, 판매 주소, 재고 방식, 재고 수량, 공개 상태와 이미지
- 누락값, 최대 길이, 숫자 범위, 잘못된 URL, 허용되지 않은 이미지 형식과 용량 초과

### 완료 조건

- 필드별 오류가 해당 입력 항목과 연결된다.
- 검증 실패 뒤 사용자가 입력한 값이 유지된다.
- 저장 전에 뉴스와 상품의 공개 결과를 확인한다.
- Supabase 미설정 상태가 처리되지 않은 예외를 발생시키지 않는다.
- 실제 저장 경로는 기존 관리자 인증을 계속 요구한다.

## 8. 작업 영역 C: 회원·댓글 시연 흐름

### 대상

- `app/login`
- `app/news/[id]/comments-panel.tsx`
- `lib/member/demo-session.ts`
- `lib/comments/domain.ts`
- 회원·댓글 관련 테스트

### 시연 역할

- 비로그인 방문자
- 일반 시연 회원
- 댓글 작성자
- 다른 회원
- 관리자 역할 예시

### 동작

- 비로그인 방문자에게 댓글 작성 전 로그인 필요 상태를 표시한다.
- 시연 회원은 댓글, 답글과 반응 동작을 현재 브라우저 상태에서 체험한다.
- 작성자와 관리자 역할 예시만 해당 댓글의 관리 동작을 볼 수 있다.
- 다른 회원의 수정·삭제 동작은 도메인 규칙과 화면 모두에서 차단한다.
- 신고와 삭제는 실행 전 확인 단계를 제공한다.
- 시연 상태는 새로고침 뒤 보존을 보장하지 않으며 화면에 이를 알린다.

### 입력 안전

- 빈 내용과 공백만 있는 내용을 거부한다.
- 댓글 길이는 기존 도메인 규칙과 동일하게 공백 제거 뒤 1자 이상 2,000자 이하만 허용한다.
- 사용자 입력을 HTML로 실행하지 않는다.
- 답글은 최상위 댓글의 직접 자식인 한 단계까지만 허용하고, 답글에 작성한 답글도 같은 최상위 댓글의 직접 자식으로 처리한다.

### 완료 조건

- 역할별 허용 동작이 도메인 규칙과 화면에서 일치한다.
- 댓글이 없거나 매우 길어도 레이아웃이 깨지지 않는다.
- 사용자 입력이 스크립트로 실행되지 않는다.
- 화면에 시연 세션과 비영구 데이터임을 표시한다.

## 9. 작업 영역 D: 개인정보 문서와 기술 보안

### 개인정보 문서

- 현재 기능과 향후 연결 예정 기능을 구분해 수집 항목, 목적, 보관 기간과 삭제 절차를 정리한다.
- 개인정보처리방침과 이용약관은 `운영 전 검토용 초안`으로 표시한다.
- 확인되지 않은 사업자 정보, 연락처, 보관 기간과 법적 근거를 추측해 작성하지 않는다.

### 동의와 분석

- 분석 허용 전에는 Google Analytics 스크립트와 이벤트를 전송하지 않는다.
- 동의 거부와 철회 뒤에는 새 분석 이벤트를 전송하지 않는다.
- 이메일, 생년월일, 닉네임과 댓글 내용을 분석 데이터에 포함하지 않는다.
- 측정 ID가 없거나 형식이 잘못되면 외부 요청 없이 정지한다.

### 보안 검사

- `node_modules`, `.next`와 이미지 바이너리를 제외한 프로젝트 파일에 비밀 키 형식이 포함되지 않았는지 검사한다.
- 로그인 복귀 주소는 `/`로 시작하고 `//`로 시작하지 않는 같은 사이트 경로만 허용한다.
- 관리자 저장 액션은 서버에서 권한을 다시 검사한다.
- 성인 콘텐츠 접근 쿠키와 프록시 규칙의 기존 테스트를 유지한다.

### 완료 조건

- 동의 전, 거부 뒤와 철회 뒤의 분석 차단 테스트가 통과한다.
- 확인된 개인정보만 문서 초안에 포함된다.
- 비밀 키와 외부 이동 가능한 복귀 주소가 검사에서 차단된다.
- 법률 전문가 확인이 필요한 문구가 별도 목록으로 남는다.

## 10. 작업 영역 E: 자동 검사와 배포 준비

### 자동 검사

다음 명령을 고정된 순서로 실행한다.

```powershell
pnpm test
pnpm exec tsc --noEmit --incremental false
pnpm build
```

pnpm의 의존성 빌드 스크립트 정책으로 `sharp`와 `msw`가 차단된 현재 상태는 운영 빌드 전에 원인을 확인한다. 승인 대상 패키지와 실행 스크립트를 검토하지 않은 채 전체 빌드 권한을 허용하지 않는다.

### 수동 검사

- 메인, 굿즈, 뉴스, 커뮤니티와 대표 게임 페이지의 HTTP 응답
- 세 기본 화면 크기의 레이아웃
- 키보드 메뉴와 모달 동작
- 관리자 입력 오류와 미리보기
- 회원·댓글 시연 역할
- 개인정보 동의 허용, 거부와 변경

### 완료 조건

- 전체 테스트가 통과한다.
- TypeScript 오류가 없다.
- 운영 빌드가 성공한다.
- 주요 페이지가 HTTP 200으로 응답한다.
- 브라우저 콘솔에 처리되지 않은 오류가 없다.
- 외부 서비스 미연결 항목과 법률 검토 항목이 배포 전 체크리스트에 남는다.

## 11. 오류 처리 원칙

- 설정 누락은 일반 방문자에게 내부 오류나 비밀 값을 노출하지 않는다.
- 데이터 없음과 요청 실패를 서로 다른 안내 문구로 표현한다.
- 정적 자원 누락은 자동 검사에서 파일 경로와 참조 위치를 보고한다.
- 개발용 미리보기 접근 거부는 존재하지 않는 공개 기능처럼 처리한다.
- 테스트와 빌드 실패는 우회하지 않고 원인과 재현 명령을 기록한다.

## 12. 작업 분리와 순서

전체 범위는 다음 다섯 개의 독립 실행 계획으로 나눈다.

1. 공개 사이트 품질·접근성 점검
2. 관리자 입력 화면과 로컬 미리보기
3. 회원·댓글 시연 UX와 권한 규칙
4. 개인정보 문서와 기술 보안 검사
5. 전체 자동 검사와 배포 준비

각 계획은 자체 실패 테스트와 완료 조건을 가지며, 앞 계획의 결과를 다음 계획의 전제 조건으로 사용하지 않는다. 다만 전체 회귀 검사는 매 계획의 마지막에 반복한다.

## 13. 최종 완료 조건

- 외부 계정 없이 공개 사이트와 모든 시연 흐름을 로컬에서 검사한다.
- 시연 데이터와 실제 운영 데이터를 명확하게 구분한다.
- 개발용 기능이 운영 환경의 인증과 저장 기능을 우회하지 않는다.
- 공개 사이트의 반응형 화면과 핵심 키보드 조작을 검증한다.
- 개인정보 동의와 비밀 정보 보호 검사가 통과한다.
- 전체 테스트, TypeScript 검사와 운영 빌드가 통과한다.
- Supabase, YouTube, GA4, 판매처, Vercel과 공식 도메인은 후속 연결 항목으로 유지한다.
