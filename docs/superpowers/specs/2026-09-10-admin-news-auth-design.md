# DEVFORGE 관리자 뉴스 작성 및 인증 설계

---

## 목적

DEVFORGE 개발자가 인터넷에서 안전하게 로그인하여 개발 뉴스를 작성·수정·삭제하고, 공개 개발 뉴스 페이지에서 게시물을 확인할 수 있게 한다. 현재는 로컬 주소와 Vercel 기본 주소를 사용하며, 공식 출시 시 코드 변경 없이 환경 설정과 인증 허용 주소만 커스텀 도메인으로 교체할 수 있어야 한다.

---

## 1차 구현 범위

- 관리자 이메일·비밀번호 로그인
- 관리자 로그인·로그아웃 상태 표시
- 관리자 전용 새 글 작성 화면
- 제목, 요약, 본문, 태그, 대표 이미지, 공개 상태 입력
- 게시물 작성·수정·삭제
- 공개된 게시물의 개발 뉴스 목록 표시
- 기존 태그 필터 유지
- 이미지 형식과 크기 검증
- Supabase 설정 예제와 데이터베이스 정책 제공
- 로컬·Vercel·향후 커스텀 도메인 전환 지원

일반 사용자 로그인, 댓글, 이모티콘 반응, 댓글 이미지 첨부는 이번 범위에서 제외한다. 해당 기능은 관리자 게시 기능이 안정된 뒤 별도 단계로 구현한다.

---

## 기술 구성

- 화면과 서버 경계: 기존 Next.js 16 프로젝트
- 사용자 인증: Supabase Auth 이메일·비밀번호 방식
- 게시물 저장: Supabase Postgres
- 이미지 저장: Supabase Storage
- 배포 대상: Vercel
- 공개 주소: 현재 Vercel 기본 주소, 출시 후 커스텀 도메인

Supabase 프로젝트가 없는 현재 상태에서는 코드, 데이터베이스 설정 SQL, 환경 변수 예제, 화면 및 로컬 자동 검증까지 완료한다. 실제 원격 로그인·저장·이미지 업로드 검증은 Supabase 프로젝트 URL과 공개 키가 등록된 뒤 수행한다.

---

## 화면 구조

### 공개 개발 뉴스

기존 `public/devlog.html`의 외형과 태그 필터 경험을 유지한다. Supabase가 설정된 환경에서는 공개 상태인 게시물을 최신순으로 불러오며, 설정되지 않은 로컬 환경에서는 기존 임시 뉴스가 표시된다. 관리자 기능으로 들어가는 링크는 일반 방문자의 주요 동선을 방해하지 않는 위치에 둔다.

### 관리자 로그인

`/admin/login`에서 이메일과 비밀번호를 입력한다. 로그인 실패, 설정 누락, 권한 없음 상태를 서로 다른 안내로 표시한다. 로그인된 관리자는 글쓰기 화면으로 이동하고, 일반 사용자는 관리자 화면에 접근할 수 없다.

### 관리자 글쓰기

`/admin/news/new`에서 제목, 요약, 본문, 태그, 대표 이미지, 공개 여부를 편집한다. 입력 화면은 제목 영역, 편집 도구, 본문 영역, 이미지 첨부, 발행 설정으로 구분한다. 초기 버전의 본문은 안전한 일반 텍스트와 줄바꿈을 저장하며 임의 HTML 입력은 허용하지 않는다.

---

## 데이터 구조

### `news_posts`

- `id`: 게시물 UUID
- `title`: 제목
- `summary`: 목록용 요약
- `content`: 본문 일반 텍스트
- `tags`: 태그 문자열 배열
- `cover_image_path`: Storage 내부 이미지 경로
- `status`: `draft` 또는 `published`
- `author_id`: Supabase 사용자 UUID
- `created_at`: 생성 시각
- `updated_at`: 수정 시각
- `published_at`: 공개 시각

공개 페이지는 `published` 게시물만 읽는다. 관리자 계정만 모든 게시물을 작성·수정·삭제할 수 있다.

---

## 인증과 권한

관리자 이메일은 `ADMIN_EMAIL` 서버 환경 변수와 Supabase의 관리자 허용 정책에서 관리한다. 브라우저에 관리자 비밀번호나 서비스 역할 키를 포함하지 않는다.

서버 보호와 Supabase Row Level Security를 함께 적용한다.

- 로그인 성공만으로 관리자 권한을 부여하지 않음
- 서버에서 로그인 세션과 관리자 이메일을 함께 확인
- 데이터베이스에서 관리자 이메일 조건을 다시 확인
- 공개 사용자는 공개 게시물 읽기만 허용
- 초안 읽기와 모든 쓰기 작업은 관리자만 허용
- 이미지 업로드 경로도 관리자 전용 정책 적용

관리자 계정에는 고유하고 긴 비밀번호를 사용한다. Supabase에서 다중 인증을 사용할 수 있는 시점에는 관리자 계정에 적용한다.

---

## 이미지 처리

대표 이미지는 JPG, PNG, WebP 형식만 허용한다. 초기 최대 크기는 5MB로 제한한다. 브라우저 검증과 Storage 정책을 함께 사용하며, 표시할 때는 저장소가 생성한 안전한 URL만 사용한다. 업로드 실패 시 게시물 저장과 구분된 오류를 표시하여 사용자가 원인을 확인할 수 있게 한다.

---

## 데이터 흐름

1. 관리자가 로그인 화면에서 Supabase Auth 인증 수행
2. 관리자 화면 진입 시 서버에서 세션과 이메일 허용 목록 확인
3. 대표 이미지가 있으면 관리자 전용 Storage 경로로 업로드
4. 게시물 입력값 검증 후 `news_posts`에 저장
5. 공개 뉴스 페이지에서 `published` 게시물을 최신순으로 조회
6. 기존 태그 버튼으로 조회 결과를 브라우저에서 필터링

---

## 오류 처리

- Supabase 미설정: 설정이 필요하다는 관리자 안내와 기존 공개 뉴스 유지
- 로그인 실패: 계정 정보 불일치 안내
- 권한 없음: 관리자 계정이 아니라는 안내 후 관리자 화면 차단
- 입력 누락: 필드별 오류 표시
- 이미지 오류: 형식·크기·업로드 실패 원인 구분
- 게시물 저장 실패: 작성 내용 유지와 재시도 안내
- 공개 조회 실패: 기존 임시 뉴스 또는 오류 상태 표시

오류 메시지에는 내부 키, 데이터베이스 세부 정보, 세션 값, 비밀번호를 포함하지 않는다.

---

## 도메인 전환

개발 단계에서는 `http://localhost:3000`과 Vercel 기본 주소를 Supabase 허용 리디렉션 주소에 등록한다. 공식 출시 시 다음 설정만 변경한다.

- Vercel 프로젝트에 커스텀 도메인 연결
- Supabase Site URL을 커스텀 도메인으로 변경
- Supabase Redirect URLs에 커스텀 도메인 추가
- 기존 Vercel 주소를 커스텀 도메인으로 이동 처리
- 검색엔진 대표 URL을 커스텀 도메인으로 지정

게시물 데이터와 관리자 계정은 그대로 유지한다.

---

## 검증 기준

- Supabase 미설정 상태에서도 기존 공개 사이트가 정상 표시됨
- 미로그인 사용자가 관리자 작성 화면에 접근할 수 없음
- 관리자 이메일이 아닌 계정은 작성 권한이 없음
- 제목과 본문이 없는 게시물은 저장되지 않음
- 허용되지 않은 이미지 형식과 5MB 초과 파일이 거부됨
- 공개 게시물만 개발 뉴스 목록에 표시됨
- 기존 태그 필터가 동적 게시물에도 적용됨
- 모바일과 데스크톱에서 로그인·글쓰기 화면을 사용할 수 있음
- 빌드와 자동 테스트가 통과함

Supabase 프로젝트 생성 전에는 원격 인증, 데이터 저장, Storage 정책의 실제 동작을 완료로 판정하지 않는다.
