# 공개 게임 소개 페이지와 내부 기획 문서 분리 설계

---
## 1. 목적

DEVFORGE 방문자가 각 게임의 핵심을 빠르게 이해하도록 공개 페이지를 소개 중심으로 정리한다.

개발용 기획 내용과 미확정 정보는 웹 공개 경로에서 분리하되 기존 자료는 삭제하지 않는다.

---
## 2. 현재 상태

`public`에는 35개 프로젝트의 메인 HTML이 있다.

정적 문구와 페이지 구조를 기준으로 다음 세 그룹이 확인됐다.

| 그룹 | 프로젝트 | 수량 | 현재 특징 |
|---|---|---:|---|
| 소개형 | A, B, C, D, H, L, η | 7 | 독자적인 소개·시스템·세계관 내용 보유 |
| 콘셉트 초안형 | γ, δ, ε, ζ, θ, ι | 6 | 짧은 소개와 장르만 제공 |
| 준비 중 템플릿형 | E, F, G, I, J, K, M, N, O, P, Q, R, S, T, U, V, W, X, Y, Z, α, β | 22 | `기획 준비 중` 문구 중심 |

메인 게임 카드 23개에는 `기획서 ✔` 문구가 노출되고 일부 브라우저 제목에는 `기획서`, `기획 초안`, `아카이브`가 포함된다.

---
## 3. 범위

이번 단계에서 다음 작업을 수행한다.

- 공개 프로젝트 데이터의 단일 기준 생성
- 공통 공개 소개 페이지 템플릿 생성
- 준비 중 프로젝트용 간결한 소개 화면 생성
- 기존 상세 기획 HTML을 웹 공개 경로 밖으로 보존
- 메인 카드의 내부 문서형 문구 제거
- 기존 특화 페이지의 디자인과 기능 유지
- 직접 주소, 성인 인증, 반응형 화면 회귀 검사

다음 항목은 이번 단계에서 제외한다.

- Supabase 관리자 인증
- 관리자 전용 웹 문서 편집기
- 기획 문서 암호화
- 실제 출시 링크와 플랫폼 API
- 프로젝트별 신규 원화 제작

---
## 4. 공개 상태 모델

프로젝트 공개 상태는 다음 세 값으로 통일한다.

| 값 | 화면 문구 | 사용 기준 |
|---|---|---|
| `featured` | 대표 프로젝트 | 소개와 시각 자료가 충분한 프로젝트 |
| `developing` | 개발 중 | 기본 콘셉트와 개발 방향이 확정된 프로젝트 |
| `planning` | 기획 단계 | 세부 내용이 확정되지 않은 프로젝트 |

개발 작업 상태는 기존 게임 목록 필터의 `개발 중`, `기획`, `보류`를 유지한다. 공개 등급과 개발 작업 상태는 서로 다른 데이터로 관리한다.

---
## 5. 공개 데이터 구조

`public/game-projects.mjs`를 프로젝트 공개 정보의 단일 기준으로 사용한다.

각 프로젝트는 다음 필드를 가진다.

- `id`: 프로젝트 식별자
- `symbol`: 화면 표시 문자
- `title`: 공개 제목
- `tagline`: 한 문장 소개
- `genres`: 장르 목록
- `developmentStatus`: 개발 중·기획·보류
- `publicationStatus`: 대표·개발 중·기획 단계
- `summary`: 공개용 짧은 설명
- `features`: 공개 가능한 핵심 특징
- `heroImage`: 대표 이미지 경로
- `detailPath`: 상세 주소
- `adultOnly`: 성인 인증 필요 여부
- `layout`: 공통·특화 페이지 구분

메인 목록과 공통 소개 페이지가 같은 데이터를 사용하도록 구성해 상태 문구가 서로 달라지는 문제를 줄인다.

---
## 6. 페이지 구조

### 공통 소개 페이지

소개형 프로젝트의 기본 순서는 다음과 같다.

1. 대표 이미지, 제목, 한 문장 소개
2. 장르, 개발 상태, 대상 플랫폼
3. 공개 가능한 핵심 특징 3~5개
4. 이미지 또는 영상 영역
5. 최신 개발 뉴스 연결
6. 커뮤니티 연결
7. 메인 게임 목록 복귀

### 준비 중 페이지

자료가 부족한 프로젝트는 빈 카드 목록을 노출하지 않는다.

다음 내용만 표시한다.

- 프로젝트명
- 장르
- 개발 상태
- 한 문장 콘셉트
- `새로운 정보가 준비되는 대로 공개됩니다` 안내
- 개발 뉴스와 메인 목록 이동 버튼

### 특화 페이지

Project B, C, D, H, L, η처럼 전용 디자인이나 기능이 있는 페이지는 유지한다.

다만 브라우저 제목, 상단 소개 문구, 내부 문서형 표현은 공개 기준에 맞게 정리한다.

---
## 7. 내부 자료 보존

35개 기존 메인 HTML 원본을 저장소 루트의 `internal/project-archives`에 동일한 프로젝트별 경로로 복사해 보존한 뒤 `public`의 파일을 공개 페이지로 교체한다.

이 디렉터리는 Next.js의 `public` 밖에 있으므로 배포된 웹 주소로 직접 접근할 수 없다.

단, GitHub 저장소 자체가 공개 저장소라면 파일 내용은 GitHub에서 계속 볼 수 있다. 실제 기밀 자료는 별도 비공개 저장소로 분리해야 한다.

이번 단계의 보안 목표는 `웹사이트 공개 경로에서 제외`이며 `저장소 접근자에게도 비공개`는 아니다.

---
## 8. 기존 기능 보존

다음 동작은 변경 후에도 유지한다.

- 메인 게임 검색
- 장르와 개발 상태 필터
- 대표 프로젝트 6개
- 12개씩 더 보기
- 성인 프로젝트 모자이크
- 직접 주소 성인 인증
- PC·태블릿·모바일 구성
- 공통 헤더와 기기 선택기
- 커뮤니티 게임 선택 연결

Project η의 초대장 연출과 합성 도감도 유지한다.

---
## 9. 오류와 예외 처리

- 등록되지 않은 프로젝트 주소는 메인 게임 목록으로 안내
- 대표 이미지 누락 시 공통 대체 이미지와 텍스트 표시
- 공개 데이터 누락 시 준비 중 화면으로 안전하게 전환
- 성인 프로젝트는 공개 데이터와 무관하게 기존 인증 절차 우선 적용
- 내부 보관 파일은 공개 페이지에서 링크하지 않음

---
## 10. 접근성과 반응형

- 제목 계층을 페이지당 하나의 `h1`부터 순서대로 구성
- 이미지에 프로젝트별 대체 설명 제공
- 상태를 색상만으로 구분하지 않고 문구 병기
- 키보드로 모든 이동 버튼 사용 가능
- 모바일 1열, 태블릿 2열, PC 확장형 구성
- 긴 제목과 장르 목록의 줄바꿈 허용

---
## 11. 테스트 기준

자동 테스트는 다음 조건을 검증한다.

- 35개 프로젝트 데이터의 식별자 중복 없음
- 모든 메인 카드에 유효한 상세 주소 존재
- 공개 페이지 제목에 `기획서`, `기획 초안`, `메인 아카이브` 미노출
- 준비 중 프로젝트에 내부 시스템 카드 미노출
- 특화 페이지 기능 유지
- 성인 프로젝트 보호 유지
- 검색과 필터 결과 유지
- 모든 공개 HTML의 공통 반응형 자원 유지
- 내부 보관 파일이 `public` 아래에 존재하지 않음

브라우저 검사는 PC, 태블릿 가로, 모바일에서 대표 프로젝트와 준비 중 프로젝트를 각각 확인한다.

## 12. 구현 단계

1. 현재 HTML 원본 보관
2. 공개 프로젝트 데이터 모듈 작성
3. 공통 소개 페이지 렌더러와 스타일 작성
4. 준비 중 22개 프로젝트 변환
5. 콘셉트 초안형 6개 프로젝트 변환
6. 소개형 7개 프로젝트의 공개 문구 정리
7. 메인 카드 상태 문구와 공개 데이터 연결
8. 성인 인증과 특화 기능 회귀 검사
9. 전체 테스트와 브라우저 확인

---
## 13. 완료 기준

- 방문자가 모든 프로젝트에서 장르, 상태, 핵심 콘셉트를 확인할 수 있음
- 공개 화면에 개발자용 문서 제목과 빈 기획 카드가 노출되지 않음
- 기존 기획 자료가 삭제되지 않고 웹 공개 경로 밖에 보존됨
- 대표·개발 중·기획 단계가 일관된 데이터로 표시됨
- 기존 성인 인증과 반응형 기능의 회귀 없음
