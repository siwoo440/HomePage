# DEVFORGE 일반 사용자·댓글 기반 설계

---

## 목표

Supabase 프로젝트가 없는 현재에도 로그인, 프로필, 댓글, 답글, 반응, 이미지 첨부, 신고 흐름의 화면과 경계를 검증한다. 출시 단계에서는 화면을 다시 만들지 않고 데이터 연결부만 Supabase로 전환한다.

---

## 범위

- 모든 공용 헤더의 오른쪽 작업 순서를 `문의하기 → 로그인`으로 통일
- 일반 사용자 로그인 페이지 추가
- 이메일 로그인과 Google 로그인 진입점 제공
- Supabase 미설정 상태에서 명확한 시연 모드 제공
- 개발 뉴스 상세 페이지에 댓글·답글·반응·이미지·신고 화면 추가
- 임시 뉴스도 상세 페이지에서 댓글 화면을 확인할 수 있도록 시연 상세 경로 제공
- 댓글과 신고를 위한 Supabase 테이블·Storage·RLS 설계 추가
- 관리자와 일반 사용자 권한을 분리

이번 단계에서 실제 이메일 전송, Google OAuth 승인, 영구 댓글 저장, 실제 이미지 업로드는 수행하지 않는다. 해당 기능은 Supabase 프로젝트 연결 뒤 활성화한다.

---

## 사용자 흐름

1. 사용자는 헤더 오른쪽의 `로그인` 버튼을 선택한다.
2. `/login`에서 이메일 또는 Google 로그인을 선택한다.
3. Supabase 미설정 상태에서는 실제 비밀번호를 받지 않고 `시연 계정으로 화면 확인`만 제공한다.
4. 시연 계정은 브라우저 세션 동안만 유지되며 보안 인증으로 취급하지 않는다.
5. 사용자는 개발 뉴스 상세 페이지에서 댓글 영역을 확인한다.
6. 시연 모드에서는 댓글 작성·답글·반응·이미지 미리보기·신고 동작을 브라우저 메모리에서 시험한다.
7. Supabase 연결 뒤 같은 화면이 서버 데이터와 실제 로그인 세션을 사용한다.

---

## 헤더 구성

공용 페이지의 오른쪽 영역은 다음 순서를 사용한다.

`문의하기` → `로그인`

로그인 상태에서는 `로그인`이 사용자 닉네임 버튼으로 바뀔 수 있도록 `data-member-action` 식별자를 둔다. 현재 구현에서는 로그인 화면으로 이동하는 링크를 제공한다.

적용 대상은 메인, 굿즈, 개발 뉴스, 커뮤니티 페이지다.

---

## 로그인 구조

로그인 화면은 서버 설정 여부에 따라 두 상태를 가진다.

- Supabase 설정됨: 이메일 입력, 비밀번호 입력, 이메일 로그인, Google 로그인
- Supabase 미설정: 입력 비활성화, 설정 대기 안내, 시연 계정 진입

시연 계정은 `sessionStorage`에 공개된 표시 정보만 저장한다. 이메일, 비밀번호, 토큰은 저장하지 않는다. 브라우저를 닫으면 시연 상태가 사라진다.

실제 인증 연결부는 `MemberAuthAdapter` 계약으로 분리한다. 화면은 인증 방식과 직접 결합하지 않는다.

---

## 댓글 구조

댓글은 다음 공통 형식을 사용한다.

- 댓글 식별자
- 뉴스 식별자
- 작성자 식별자·닉네임·프로필 이미지
- 본문
- 선택 이미지
- 부모 댓글 식별자
- 작성·수정 시각
- 공개·숨김·삭제 상태
- 이모티콘별 반응 수와 현재 사용자 선택

답글은 한 단계만 허용한다. 삭제된 댓글은 답글이 있으면 자리 표시만 남긴다. 숨김 댓글은 관리자 안내로 대체한다.

---

## 댓글 화면

뉴스 본문 아래에 다음 순서로 배치한다.

1. 댓글 수와 로그인 상태
2. 댓글 입력기
3. 이미지 선택과 미리보기
4. 댓글 목록
5. 답글 입력기
6. 이모티콘 반응
7. 신고 메뉴

로딩, 댓글 없음, 통신 오류, 미로그인, 전송 중, 신고 완료 상태를 각각 구분한다.

---

## 신고와 운영 규칙

신고 사유는 스팸, 욕설·괴롭힘, 음란물, 개인정보 노출, 기타로 제한한다. 한 사용자는 같은 댓글을 한 번만 신고할 수 있다.

실제 서버 연결 뒤에는 관리자만 신고 목록을 읽고 댓글 숨김·복구·삭제와 사용자 차단을 수행한다. 처리 기록에는 관리자, 조치, 대상, 시각을 남긴다.

---

## 이미지 규칙

- 허용 형식: JPEG, PNG, WebP, GIF
- 최대 크기: 5MB
- 댓글당 이미지 한 장
- 업로드 전 브라우저 미리보기
- 서버에서 형식과 크기 재검사
- 공개 댓글 이미지와 관리자 검토 이미지를 분리할 수 있는 저장 경로

시연 모드에서는 선택한 파일의 로컬 미리보기만 만들고 업로드하지 않는다.

---

## 데이터베이스 준비

추가 테이블은 `member_profiles`, `news_comments`, `comment_reactions`, `comment_reports`, `moderation_actions`다. 댓글 이미지용 비공개 검토 정책을 포함한 Storage 버킷을 추가한다.

RLS 기본 원칙은 다음과 같다.

- 공개 댓글은 누구나 읽기 가능
- 로그인 사용자만 자신의 댓글 작성·수정·삭제 가능
- 로그인 사용자만 자신의 반응·신고 관리 가능
- 관리자만 숨김 댓글, 신고 목록, 운영 기록 접근 가능
- 차단된 사용자는 새 댓글 작성 불가

---

## 시연 뉴스 상세

현재 임시 개발 뉴스 네 개는 고유한 시연 식별자를 갖고 `/news/<demo-id>`로 이동한다. Supabase가 없어도 뉴스 본문과 댓글 화면을 확인할 수 있다. 실제 게시물은 기존 UUID 경로를 그대로 사용한다.

---

## 오류 처리

- Supabase 미설정: 시연 모드 안내
- 인증 만료: 로그인 화면 이동 안내
- 댓글 저장 실패: 입력 내용 유지와 재시도 안내
- 이미지 오류: 본문은 유지하고 이미지 오류만 표시
- 신고 중복: 이미 접수된 신고 안내
- API 오류: 기존 댓글 목록 유지

시연 모드와 실제 인증 상태를 혼동하지 않도록 모든 관련 화면에 상태 배지를 표시한다.

---

## 보안 경계

- 비밀번호와 인증 토큰을 직접 저장하지 않음
- 클라이언트의 관리자 표시를 권한 근거로 사용하지 않음
- 서버와 RLS에서 소유권·관리자 권한 이중 검사
- 댓글 문자열을 HTML로 직접 삽입하지 않음
- 이미지 이름과 형식을 서버에서 재검사
- 신고·댓글 API에 요청 횟수 제한을 연결할 수 있는 경계 제공

---

## 검증 기준

- 네 공용 페이지에서 문의하기 다음에 로그인 버튼 표시
- 로그인 버튼이 `/login`으로 이동
- Supabase 미설정 상태에서 실제 비밀번호 제출 차단
- 시연 계정 상태가 브라우저 세션에만 유지
- 네 임시 뉴스가 각 시연 상세 페이지로 이동
- 뉴스 상세에서 댓글·답글·반응·이미지 미리보기·신고 흐름 확인
- 입력 문자열이 HTML로 실행되지 않음
- 댓글 이미지 형식·5MB 제한 적용
- 데이터베이스 RLS에 공개 읽기, 본인 쓰기, 관리자 조치 분리
- 기존 관리자·상품·뉴스·커뮤니티·성인 보호 테스트 유지
