# DEVFORGE 반응형 내비게이션·기기 미리보기 설계

## 1. 목적

DEVFORGE의 기존 PC 디자인을 유지하면서 태블릿 가로와 모바일 화면에서도 모든 주요 페이지에 접근할 수 있는 공통 내비게이션과 레이아웃 기준을 제공한다. 개발자는 별도 미리보기 페이지에서 PC·태블릿 가로·모바일 화면을 버튼으로 전환해 실제 미디어 쿼리 결과를 확인할 수 있어야 한다.

## 2. 사용자와 성공 기준

### 방문자

- 실제 브라우저 너비에 따라 이 문서의 모바일·태블릿·PC 구성을 자동으로 사용한다.
- 모바일 헤더에서도 게임·굿즈·개발 뉴스·커뮤니티·문의·로그인에 접근한다.
- 키보드와 터치로 메뉴를 열고 닫고 이동한다.
- 모바일에서 본문 가로 스크롤이나 겹침 없이 콘텐츠를 읽는다.

### 개발자

- `device-preview.html`에서 검사할 페이지를 선택한다.
- PC 1440×900, 태블릿 가로 1024×768, 모바일 390×844 프레임을 버튼으로 전환한다.
- 실제 페이지를 iframe에 불러와 각 페이지의 미디어 쿼리 결과를 확인한다.
- 대상 페이지를 새 창에서 열어 실제 브라우저 반응형 동작을 확인한다.

## 3. 범위

### 1차 적용 페이지

- `public/main.html`
- `public/goods.html`
- `public/devlog.html`
- `public/community.html`
- `public/project_eta/ProjectEta_Main.html`

### 확대 적용 페이지

1차 검증을 통과한 공통 CSS와 모듈을 나머지 공개 HTML 페이지에 연결한다. 페이지별 고유 콘텐츠와 시각 연출은 유지하며 공통 헤더·푸터·본문 폭·터치 영역만 동일한 기준을 사용한다.

### 제외 범위

- 일반 방문자용 헤더에 PC·태블릿·모바일 전환 버튼을 노출하지 않는다.
- 이번 작업에서 모든 정적 HTML을 Next.js 페이지로 변환하지 않는다.
- Google Ads, Google Analytics, Supabase 실제 연결은 변경하지 않는다.
- 프로젝트별 콘텐츠와 게임 기획 내용은 수정하지 않는다.

## 4. 반응형 기준

### 모바일

- 범위: `0px`부터 `767px`
- 상단 표시: 로고, 로그인, 햄버거 버튼
- 메뉴: 화면 오른쪽에서 열리는 공통 메뉴 패널
- 게임·뉴스·굿즈: 기본 1열
- 커뮤니티: 기본 2열, 매우 좁은 화면에서는 1열 허용
- 조작 영역: 최소 높이와 너비 `44px`
- 호버에서만 보이는 정보는 항상 보이거나 터치로 접근 가능

### 태블릿 가로

- 범위: `768px`부터 `1279px`
- `768px`부터 `959px`: 로고, 로그인, 햄버거 버튼
- `960px`부터 `1279px`: 로고, 축약된 주요 메뉴, 문의, 로그인
- 게임·굿즈: 콘텐츠 폭에 따라 2~3열
- 커뮤니티: 3열 2행
- 프로젝트 에타의 합성 도감: 내부 가로 스크롤 유지

### PC

- 범위: `1280px` 이상
- 기존 전체 메뉴와 디자인 유지
- 게임: 3~4열
- 굿즈: 4열
- 커뮤니티: 6개 카드 가로 배치

## 5. 공통 내비게이션

### 메뉴 항목

- 게임
- 굿즈
- 개발 뉴스
- 커뮤니티
- 문의하기
- 로그인 또는 로그아웃 상태
- 홈으로 이동

### 모바일 동작

1. 햄버거 버튼을 선택하면 메뉴 패널과 반투명 배경을 표시한다.
2. 문서 본문의 스크롤을 잠근다.
3. 열린 메뉴의 첫 번째 링크로 포커스를 이동한다.
4. `Tab`과 `Shift+Tab` 포커스가 열린 메뉴 밖으로 빠져나가지 않게 한다.
5. `Escape`, 닫기 버튼, 배경 선택, 메뉴 링크 이동으로 메뉴를 닫는다.
6. 닫을 때 햄버거 버튼으로 포커스를 되돌린다.
7. 페이지가 `960px` 이상으로 바뀌면 열린 메뉴를 자동으로 닫는다.

### 접근성 속성

- 햄버거 버튼: `aria-expanded`, `aria-controls`, 설명 가능한 이름
- 메뉴 패널: `aria-hidden`과 고유 식별자
- 닫기 버튼: `aria-label`
- 현재 페이지 메뉴: `aria-current="page"`
- 배경과 숨겨진 메뉴는 키보드 탐색에서 제외

## 6. 공통 파일 구조

### HTML 연결 규칙

- 공통 헤더 루트에 `data-responsive-nav-root`를 추가한다.
- `responsive-nav.mjs`는 헤더 루트 안에 햄버거 버튼을 한 번만 추가한다.
- 메뉴 패널과 오버레이는 `body`의 마지막 자식으로 한 번만 추가한다.
- 공통 링크는 루트 절대 경로 `/main.html#games`, `/goods.html`, `/devlog.html`, `/community.html`, `/login`을 사용해 중첩된 프로젝트 페이지에서도 동일하게 동작한다.
- 문의 메뉴는 `/main.html#contact`로 이동하며 메인 페이지가 해당 해시를 감지해 기존 문의 모달을 연다.
- 로그인 링크에는 `data-member-action`을 부여해 기존 회원 상태 모듈이 로그인·로그아웃 표시를 갱신할 수 있게 한다.
- 각 HTML은 닫는 `body` 태그 직전에 `responsive-nav.mjs`를 한 번만 불러온다.

### `public/responsive-shell.css`

- 세 화면 구간의 공통 변수와 레이아웃 규칙
- 공통 헤더, 모바일 메뉴, 오버레이, 본문 폭, 터치 영역
- `prefers-reduced-motion` 대응
- 페이지별 기존 CSS보다 명확한 공통 선택자 사용

### `public/responsive-nav.mjs`

- 모바일 메뉴 초기화
- 공통 메뉴 마크업의 중복 없는 생성
- 열기·닫기·포커스 순환·스크롤 잠금
- 중복 초기화 방지
- 필요한 DOM 요소가 없는 페이지에서는 오류 없이 종료

### `public/device-preview.html`

- 개발용 도구 모음
- 대상 페이지 선택
- PC·태블릿 가로·모바일·화면 맞춤 버튼
- 미리보기 iframe
- 현재 크기와 페이지 표시

### `public/device-preview.css`

- 개발 도구 모음과 프레임 외곽 디자인
- 작은 화면에서 도구 모음 줄바꿈
- 프레임이 화면보다 큰 경우 양방향 스크롤 제공

### `public/device-preview.mjs`

- 허용된 내부 HTML 경로 목록 관리
- 선택된 프레임 크기 적용
- 쿼리 문자열의 페이지·기기 상태 복원
- 잘못된 외부 주소와 등록되지 않은 내부 경로 차단
- 새 창 열기 주소 생성

## 7. 데이터 흐름

### 실제 사이트

1. HTML이 `responsive-shell.css`를 불러온다.
2. 브라우저 너비에 따라 CSS 미디어 쿼리가 구성을 선택한다.
3. `responsive-nav.mjs`가 공통 메뉴 요소를 찾는다.
4. 모바일에서만 햄버거 메뉴 상호작용을 활성화한다.

### 미리보기 도구

1. 사용자가 허용된 페이지를 선택한다.
2. 선택한 페이지를 iframe의 `src`에 설정한다.
3. 기기 버튼이 iframe 외곽의 정확한 너비와 높이를 설정한다.
4. iframe 내부 문서는 해당 뷰포트 크기에 따라 자체 미디어 쿼리를 적용한다.
5. 현재 페이지와 기기 상태를 URL 쿼리에 기록해 새로고침 후 복원한다.

## 8. 오류 처리

- 대상 페이지가 없으면 미리보기 영역에 오류 안내를 표시한다.
- 외부 URL, `javascript:` URL, 상위 폴더 이동 경로는 허용하지 않는다.
- 공통 메뉴 요소가 없는 페이지에서 스크립트 예외를 발생시키지 않는다.
- iframe 로드 실패 시 선택 메뉴와 기기 버튼은 계속 사용할 수 있어야 한다.
- 모바일 메뉴가 열린 상태에서 화면 크기가 변하면 스크롤 잠금을 해제한다.

## 9. 디자인 원칙

- 현재 DEVFORGE의 어두운 네이비, 시안, 보라색 시각 언어를 유지한다.
- 모바일 메뉴는 기존 페이지 위에 겹쳐 표시하되 본문 내용은 수정하지 않는다.
- 태블릿은 PC 화면의 단순 축소가 아니라 간격과 열 개수를 조정한다.
- 모바일에서는 작은 영문 보조 문구보다 게임명과 핵심 행동 버튼을 우선한다.
- 고유 프로젝트 페이지의 테마 색상은 공통 내비게이션 구조와 충돌하지 않게 유지한다.

## 10. 테스트 전략

### 자동 테스트

- 모든 핵심 페이지가 공통 CSS와 메뉴 모듈을 같은 순서로 불러오는지 검사한다.
- 모바일 메뉴의 필수 항목과 접근성 속성을 검사한다.
- 메뉴 열기·닫기·포커스 복귀·너비 변경 동작을 DOM 대역으로 검사한다.
- 미리보기 기기별 크기 값을 검사한다.
- 허용되지 않은 iframe 주소가 차단되는지 검사한다.
- 기존 전체 테스트를 실행해 뉴스·굿즈·커뮤니티·성인 인증 기능의 회귀를 확인한다.

### 화면 검증

- 390×844 모바일
- 767px 모바일 상한
- 768px 태블릿 하한
- 1024×768 태블릿 가로
- 1279px 태블릿 상한
- 1280px PC 하한
- 1440×900 PC

각 화면에서 헤더, 메뉴, 카드 열, 모달, 개인정보 설정, 성인 콘텐츠 가림, 프로젝트 에타 초대장과 합성 도감을 확인한다.

## 11. 적용 순서

1. 공통 반응형 CSS와 내비게이션 모듈의 실패 테스트를 작성한다.
2. 메인 페이지에 모바일 메뉴와 세 화면 구간을 적용한다.
3. 굿즈·개발 뉴스·커뮤니티 페이지를 적용한다.
4. 프로젝트 에타의 고유 연출과 합성 도감을 적용한다.
5. 개발자용 기기 미리보기 페이지를 구현한다.
6. 나머지 공개 HTML 페이지에 공통 자원을 연결한다.
7. 전체 자동 테스트와 PC·태블릿·모바일 화면 검증을 수행한다.

## 12. 완료 조건

- 모바일 헤더에서 모든 주요 페이지에 접근한다.
- 모바일 페이지에 의도하지 않은 본문 가로 스크롤이 없다.
- 햄버거 메뉴를 터치와 키보드로 모두 조작한다.
- 태블릿 가로에서 메뉴·카드·버튼이 겹치지 않는다.
- PC 화면은 기존 정보 구조와 시각적 밀도를 유지한다.
- 미리보기 도구가 세 기기 크기를 정확히 전환한다.
- 외부 또는 등록되지 않은 주소를 iframe에 넣지 못한다.
- 기존 전체 테스트, TypeScript 검사, 운영 빌드가 통과한다.
