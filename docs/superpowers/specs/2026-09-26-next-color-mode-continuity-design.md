# Next.js 색상 모드 연속 적용 설계

---
## 목표

정적 공개 페이지에서 저장한 `devforge-color-mode` 값을 Next.js 로그인·뉴스·관리자 화면에서도 첫 화면 표시 전에 복원합니다. 저장값이 없거나 사용할 수 없을 때만 운영체제의 다크 모드 설정을 따릅니다.

---
## 범위

- Next.js 루트 문서에 공통 테마 범위와 초기 색상 모드 적용 지점 추가
- 렌더링 전 실행되는 독립 초기화 스크립트 추가
- `light`, `dark`, 잘못된 값, 저장소 접근 실패와 시스템 설정 부재 검사
- 기존 정적 페이지의 메뉴·테마 버튼·저장 키 유지
- 외부 계정, API, 쿠키와 서버 저장소는 사용하지 않음

---
## 선택한 구조

`public/color-mode-bootstrap.js`를 일반 동기 스크립트로 제공하고 Next.js 문서의 테마 스타일보다 먼저 실행합니다. 스크립트는 `document.documentElement`에 `data-color-mode`를 설정합니다. 루트 `<html>`에 `data-theme="playful-lab"`를 옮겨 초기 스크립트가 `<body>` 파싱 전에도 토큰 범위를 결정할 수 있게 합니다.

이 방식은 다음 세 대안 중 초기 깜빡임 방지와 테스트 가능성이 가장 높습니다.

1. 선택안: 동기 부트스트랩 스크립트로 `<html>` 속성 설정
2. 제외안: React 수화 뒤 클라이언트 효과로 적용 — 첫 화면 색상 전환 가능성
3. 제외안: 쿠키 기반 서버 적용 — 현재 로컬 저장소 계약과 중복되고 서버 동기화 범위 증가

---
## 색상 모드 결정 규칙

1. 로컬 저장값이 `light` 또는 `dark`이면 해당 값을 사용
2. 저장값이 없거나 잘못되었으면 `prefers-color-scheme: dark` 결과 사용
3. 로컬 저장소 접근이 차단되면 시스템 설정 사용
4. 시스템 설정 API도 없으면 `light` 사용
5. 초기화 중 오류가 발생해도 페이지 렌더링을 중단하지 않음

---
## 화면 및 접근성 영향

테마 전환 버튼의 문구, 해·달 표시와 저장 동작은 기존 `responsive-nav.mjs`가 계속 담당합니다. Next.js 화면은 저장된 선택을 표현하는 역할만 추가합니다. `<html>` 속성이 브라우저에서 먼저 추가되므로 React 수화 경고를 막기 위해 루트 요소에 수화 경고 억제를 명시합니다.

---
## 검증 기준

- 저장된 다크 모드가 시스템 밝은 모드보다 우선
- 저장된 밝은 모드가 시스템 다크 모드보다 우선
- 저장값 누락·오염·저장소 예외 시 안전한 대체값 사용
- 초기화 스크립트가 공통 테마 스타일보다 먼저 배치
- 로그인·뉴스·관리자 화면을 포함한 모든 Next.js 경로가 같은 루트 계약 사용
- 전체 Node 테스트, TypeScript 검사와 운영 빌드 통과
