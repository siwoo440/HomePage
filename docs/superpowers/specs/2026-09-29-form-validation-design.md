# L6 입력 검증과 오류 안내 설계

---
## 목표

뉴스·상품·댓글·인증 폼에서 잘못된 입력을 저장 전에 차단하고, 동일한 검증 결과를 입력 필드 가까이에 표시하며, 첫 오류 필드로 키보드 포커스를 이동한다.

---
## 기준

- 뉴스와 상품은 기존 도메인 검증 함수를 브라우저와 서버가 함께 사용한다.
- 댓글은 기존 댓글 도메인 검증 함수를 제출 전에 실행하고 서버 검증도 유지한다.
- 서버 검증을 최종 기준으로 유지하며 브라우저 검증은 빠른 안내 역할만 맡는다.
- 오류 순서는 화면의 입력 순서를 명시적으로 따른다.
- 오류 요약은 `role="alert"`, 개별 오류는 `aria-invalid`와 `aria-describedby`로 연결한다.
- 최대 5MB와 허용 이미지 형식 검사는 업로드 전에 실행한다.
- 로그인과 연령 확인은 기존 서버 응답을 유지하면서 오류 발생 시 관련 첫 입력으로 포커스를 이동한다.

---
## 구조

1. 공용 폼 유틸리티가 오류 존재 여부, 오류 식별자, 첫 오류 필드 포커스를 담당한다.
2. 뉴스·상품 검증 모듈이 `FormData`를 도메인 입력값과 이미지로 변환한다.
3. 관리자 편집기는 제출 시 같은 도메인 검증기를 실행하고, 통과한 경우에만 서버 액션을 호출한다.
4. 댓글 패널은 내용과 이미지 오류를 분리하고 제출 중복을 차단한다.
5. 인증 폼은 서버 오류 뒤 관련 첫 입력으로 포커스를 복구한다.

---
## 오류 처리 흐름

입력 제출 → 브라우저 도메인 검증 → 실패 시 저장 차단·오류 표시·첫 오류 포커스 → 성공 시 서버 전송 → 서버 재검증 → 실패 시 동일한 오류 연결과 첫 오류 포커스 → 성공 처리

---
## 검증 범위

- 공백뿐인 필수 문자열
- 최대 길이 경계값
- 음수·소수·안전 정수 범위를 벗어난 숫자
- HTTPS가 아닌 판매 주소
- 허용되지 않은 이미지 MIME 형식
- 5MB 초과 이미지
- 빈 댓글과 2,000자 초과 댓글
- 로그인 자격 증명 오류와 연령 확인 입력 오류의 포커스 복구

---
## 완료 조건

- 잘못된 입력은 서버 저장 호출 전에 차단된다.
- 첫 오류 필드가 화면 순서대로 포커스를 받는다.
- 오류 문구가 해당 입력과 접근성 속성으로 연결된다.
- 서버 검증과 브라우저 검증이 같은 도메인 규칙을 사용한다.
- 기존 전체 테스트와 빌드가 통과한다.
