# 댓글 로컬 서비스 계층 설계

---
## 목적

댓글 화면이 직접 처리하던 조회, 작성, 한 단계 답글, 반응, 신고 규칙을 공통 서비스 계약으로 분리합니다. 현재는 외부 계정 없이 메모리 기반 로컬 저장소로 동작하며, 이후 Supabase 어댑터가 같은 계약을 구현할 수 있게 합니다.

---
## 범위

- 뉴스별 댓글 조회
- 댓글과 한 단계 답글 작성
- 댓글 내용과 이미지 메타데이터 검증
- 좋아요·응원·궁금해요 반응 추가, 취소, 전환
- 신고 사유 저장과 동일 사용자의 중복 신고 차단
- 새로고침 시 데모 초기값으로 복원되는 메모리 저장 정책
- 댓글 화면의 서비스 사용과 사용자 안내

실제 Supabase CRUD, 영구 저장, 운영용 인증, 이미지 업로드와 관리자 신고 처리는 이 단계에 포함하지 않습니다.

---
## 구조

| 파일 | 책임 |
| --- | --- |
| `lib/comments/domain.ts` | 댓글 자료형과 순수 검증·반응 규칙 |
| `lib/comments/service.ts` | 화면과 저장소가 공유하는 서비스 계약, 입력·결과·오류 형식 |
| `lib/comments/local-service.ts` | 메모리 기반 조회·작성·반응·신고 구현 |
| `app/news/[id]/comments-panel.tsx` | 입력, 이미지 미리보기, 사용자 메시지와 서비스 호출 |

서비스는 비동기 메서드를 제공하여 이후 서버 어댑터로 교체해도 화면 호출 구조를 유지합니다. 반환값은 복제하여 화면 코드가 저장소 내부 상태를 직접 변경하지 못하게 합니다.

---
## 서비스 계약

`CommentService`는 다음 동작을 제공합니다.

- `list(newsId)`: 해당 뉴스의 댓글과 답글 목록 반환
- `create(input)`: 검증된 댓글 또는 한 단계 답글 생성
- `toggleReaction(commentId, userId, reaction)`: 반응 추가·취소·전환
- `report(input)`: 신고 저장과 중복 신고 차단

작성 입력은 뉴스, 부모 댓글, 작성자, 닉네임, 내용과 선택 이미지 메타데이터를 포함합니다. 이미지 데이터 주소는 화면에서 읽고, 서비스는 MIME 형식과 크기를 검증한 뒤 주소만 댓글에 저장합니다.

---
## 검증 규칙

- 댓글은 공백 제거 후 1자 이상, 2,000자 이하
- 이미지는 JPEG, PNG, WebP, GIF 중 하나이며 5MB 이하
- 답글의 부모는 같은 뉴스에 속한 최상위 댓글
- 답글에 다시 답글을 작성할 수 없음
- 한 사용자는 한 댓글에 한 종류의 반응만 유지
- 같은 반응을 다시 선택하면 취소
- 신고 사유는 정의된 다섯 값 중 하나
- 신고 상세 내용은 공백 제거 후 최대 500자
- 같은 사용자의 같은 댓글 중복 신고 금지
- 존재하지 않는 댓글은 반응·신고 대상이 될 수 없음

---
## 오류 처리

서비스 오류는 코드와 사용자용 메시지를 함께 제공합니다. 화면은 입력 오류를 그대로 안내하고, 성공하기 전에는 입력 내용을 지우지 않습니다.

| 코드 | 의미 |
| --- | --- |
| `COMMENT_NOT_FOUND` | 대상 댓글 없음 |
| `INVALID_PARENT` | 잘못된 답글 부모 |
| `INVALID_CONTENT` | 댓글 내용 규칙 위반 |
| `INVALID_IMAGE` | 이미지 규칙 위반 |
| `INVALID_REPORT_REASON` | 지원하지 않는 신고 사유 |
| `REPORT_DETAIL_TOO_LONG` | 신고 상세 내용 500자 초과 |
| `DUPLICATE_REPORT` | 동일 사용자의 중복 신고 |

---
## 저장 정책

로컬 서비스 인스턴스는 화면이 열릴 때 데모 댓글 사본으로 시작합니다. 댓글 작성, 반응, 신고는 현재 인스턴스에만 유지되며 새로고침하면 초기화됩니다. 이는 현재 화면의 안내 문구와 일치하며 실제 영구 저장으로 오해되지 않게 합니다.

---
## 접근성과 화면 동작

- 신고 사유 선택값을 댓글별로 관리하고 실제 신고 요청에 전달
- 신고 성공 후 버튼을 비활성화하고 상태 메시지 제공
- 서비스 오류를 `role="status"` 영역에 표시
- 로그인하지 않았거나 데모 모드가 아니면 변경 작업 차단
- 댓글 수와 화면 목록을 서비스 결과 기준으로 갱신

---
## 이미지·벡터 자산 판단

이번 단계는 데이터 흐름과 상태 동작이 핵심이며 새 이미지가 의미 전달을 개선하지 않습니다. 기존 댓글 UI와 이미지 첨부 기능을 유지하고 별도 래스터·벡터 자산은 만들지 않습니다.

---
## 완료 기준

- 서비스 계약과 로컬 구현의 경계값 테스트 통과
- 댓글 화면이 직접 저장 규칙을 만들지 않고 서비스를 사용
- 선택한 신고 사유가 실제 신고 요청에 반영
- 새 서비스 인스턴스가 데모 초기 상태로 복원
- 전체 테스트, TypeScript 검사와 운영 빌드 통과
- 개발 노트와 파일 지도 갱신
